# 第四轮：合同驱动的 oracle 检查计划

目标：完整列出有限输入等价类和输出规则，在 /tmp 中逐类制造错误实现，证明两份 oracle 拒绝它们。非目标：改产品、审查提示词、mutation_checks、派发/交付断言，或证明有限用例穷尽所有程序错误。

| 合同类别 | 输入与反事实 |
| --- | --- |
| 每行的 minutes | 缺失、负整数、true/false、零/整数/小数/负小数 float、空/数字/负数/小数字符串、null、空/非空数组与对象；每个值分别位于三行输入的首/中/末。逐格放过该非法输入，另测只校验某一行的结构性变异。 |
| 每行的 name | 缺失、空串、ASCII/全角空白、制表/换行空白、null、true/false、整数/float、空/非空数组与对象；同样覆盖首/中/末与只校验某一行。其他字段总是合法，不规定双字段同时非法时的优先级。 |
| 正常聚合 | 原有五组检查保留；去首尾空白、保留内部空白、非相邻重复名合并、按 name 排序、total 总和、空数组。变异包括去空白遗漏/单侧、覆盖合计、排序遗漏/倒序/忽略大小写、错误 total、错误 JSON 数值类型。 |
| duration | 显式预期覆盖 0、59、60、61、119、120、125、6001 分钟；去分钟补零、小时补零、错误除数、无进位、分钟不取余及各边界错误分别验证。 |
| normalize 异常 | 非法输入必须抛 ValueError、消息精确为对应字段的错误；测试返回错误对象、RuntimeError/TypeError、错误消息/字段/额外文字。 |
| CLI 协议 | 实际 CLI 成功 exit 0、错误 exit 2，stdout 精确为一个 JSON 值且只有一行，无前后杂字/额外 JSON/空白行；成功与错误分开变异。结果只读 stdout；stderr 仅作诊断，允许 stderr 日志的正对照，拒绝只向 stderr 输出结果的负对照。 |
| 写入范围 | 夹具卡只允许 src/normalize.py、src/report.py，验收文件受保护；由真实 verify 的路径/oracle 门禁检查。oracle 在 reviewer 无 Git 的副本中只检查行为，不能从该副本独立证明历史写入范围。 |

两个原则：期望值来自任务卡和主控 #15 的合同清单，不从候选输出推导；失败必须是语法有效、可导入的已知坏实现触发 oracle 检查，不把补丁锚点失配、超时或导入失败计作杀死。

输入集只代表标准 JSON 的有限等价类，不包含 NaN/Infinity、无法解析的 stdin 或未定义的顶层/行容器语义。name 内部空白应保留，stderr 无须为空；这些都不得被 oracle 擅自收紧。有限变异覆盖不能证明所有合法字符串、任意大小整数或所有恶意程序的行为；独立审查仍需判断充分性。若第四轮 reviewer 再发现 oracle 缺口，按主控 #15 停下交构思主控，不自动进入第五轮。
