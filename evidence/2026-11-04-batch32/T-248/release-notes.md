Enchanted 0.1.6：项目终端改由应用内带的私有 hc core 托管，后台重启后接回原来的终端；同时修了 0.1.5 之后两次真实使用和多轮试用中发现的问题。

终端与会话：

- 项目终端由编排后台启动的私有 hc core 托管（随应用打包固定版本，与你自己的 Herdr 互不影响）。后台重启后接回原来的终端，终端里的 CLI 不中断。
- 终端里不再带私有 core 的地址，终端之间只经 `a2a` 命令往来；历史不完整的窗格在标题栏标出“历史不完整”。
- 普通项目终端里的 Claude Code 和 Codex 现在都能报上回合状态和原生会话号：标题栏不再停在“正在输入 未知”，右键“复制深度链接”可复制 CLI 名、原生会话号和记录路径。在一个 CLI 里再起另一个 CLI、CLI 装在带空格的路径下、用 npm 装的 Codex，都按实际运行的进程分开记。
- 侧栏按 CLI 显示图标和名称；agy、opencode worker 的状态取自它们报给终端的回合信号。
- 后台重启后，已消失的 worker 窗格和历史窗格不再报错或空白；关闭终端后不再报 resize 内部错误。

主控与门禁：

- 问题上报先推给执行主控处理，主控答不了的才交给你。
- 主控可以在多个已打开的项目里建任务和派发；能接 MCP 的 CLI 经 MCP 调用门禁，接不上的用 `a2a` 命令。
- 路径限制改为门禁报事实、主控判断：认领时的路径重叠和任务卡外的改动交主控决定，不再直接打回。
- 审查员经 `review_submit` 按字段交结论，不用手写嵌套 JSON；门禁拒绝时显示看得懂的原因和下一步。
- 任务页显示门禁全程，审查中、返工中显示中文状态；按 Esc 后再发消息，worker 的交付照常进门禁。
- 受管窗格里的输入按回车记一条完整消息，不再按键记录。

项目与界面：

- 项目随时可以移除；失效的仓库不再拖累其他项目的认领。
- 中文等非 ASCII 目录名正常显示；非 Git 目录不再露出原始 git 报错；安静的命令不再被误提示“可能在等 macOS 权限弹窗”。
- 复盘：CLI 退出或后台重启后不再一直显示“进行中”；复盘日程在各时区和夏令时切换日按本地日历计算。

升级提醒：

- 换版后 macOS 会收回 Enchanted 访问“文稿”等文件夹的授权（本包是 ad-hoc 签名，每个版本都算新的应用）。终端里的 CLI 读这些目录时会停下来等系统弹窗，弹窗可能被别的窗口挡住，请本人允许一次。
- 内带的 hc 是固定版本 0.1.15，直接从应用包里运行，有自己的会话名；你自己装的 Herdr 和它的 core 不受影响。
- Codex 第一次在项目终端里用到新钩子时可能弹一次钩子信任框，由你本人确认。

已知限制：

- 先按 Stop、再在同一窗格输入时，标题栏的状态曾有一次落后于后台（T-235）；之后没有复现，等再次出现时处理。
- agy、opencode 当主控时，你对它们说的话不记入用户输入；后台重启后不恢复 agy、opencode 的受管窗格。
- 应用内主控写的完成条件仍可能偏弱或写错；门禁会如实拒收，需要主控修卡重派。
- 只支持 macOS（Apple 芯片）；CLI 支持 Claude Code、Codex、agy、opencode 四种。

安装包适用于 macOS arm64（Apple Silicon）。解压后将 `Enchanted.app` 放入“应用程序”。

本包使用 ad-hoc 签名，未经 Apple 公证。首次打开如被系统拦截，可在访达中右键选择“打开”；必要时运行：

```sh
xattr -dr com.apple.quarantine /Applications/Enchanted.app
```

使用前先安装并登录至少一种支持的 CLI。bundle id 与后台数据目录保持不变。
