# 详情验收修复：先写不变量与观察矩阵

依据：门禁回执 #52，verification `10991a07-6711-4027-abb6-25d42fb69ab0`，候选 `1e1e5ef7bfb1faa8a0af8df064ac6834e2579a93`。这是同一“保留模型但断开界面功能”的第二个反例，按 evidence-first-testing 系统核对观察点，不追加盲审。

目标：现有真实 Electron 旅程从可见提交行进入详情、从可见文件按钮进入单文件 diff；期望来自夹具的真实 Git。范围是开发测试、沙箱外必跑编排及本轮证据。冻结验收、产品实现、运行时缺陷、依赖与权限不改。

不变量：

1. 点击可见提交行后，相应详情必须可见。模型返回正确结果不能代替组件挂载；no-details 必须命中“点击提交后详情可见”。
2. 详情的标题、哈希、父提交、作者、提交者、正文和文件列表须与外部 Git 相符，切换提交不能残留上一条详情。
3. 点击可见文件按钮后，对应 diff 必须可见；no-diff 必须命中“点击文件后单文件 diff 可见”。逐行比较界面 hunk 文本与 `git --literal-pathspecs`，不从产品 diffRows 或 diffArgs 生成期望。
4. 文件名中的 `*`、`[`、`:(` 都是字面文件名；根提交、普通提交和未提交三条路径均不得混入其他文件内容。
5. 没有 HEAD 时，已暂存、暂存后再修改、未暂存（intent-to-add）和未跟踪文件均可进入详情；已跟踪文件的 diff 与 Git 空树比较，未跟踪文件显示明确说明。
6. 变异红态必须来自指定业务断言。窗口启动、CDP、Git 夹具、构建或清理失败不能当作该红态。

| 用户路径／状态 | 原有观察点 | 本次补充／保留 |
| --- | --- | --- |
| 打开面板 | 面板 DOM、no-panel | 保留 |
| 提交表 | 顺序、父子、refs、未提交与 HEAD 虚线 | 保留 parents/order 反例 |
| 点提交 → 详情 | 缺失 | 可见详情、真实 Git 元数据与文件列表；no-details |
| 点文件 → diff | 缺失 | 可见 diff、独立 Git hunk 文本与行数；no-diff |
| 字面文件名 | 仅宿主 | 3 类 diff × 3 种特殊文件名，经窗口点击 |
| 首次提交前 | 仅宿主 | 独立 unborn 仓库的 4 类文件状态，经窗口点击 |
| 创建／删除分支与非法名字 | 窗口操作、Git 引用读回 | 保留 |
| cwd 跟随、固定、多仓库 | 窗口与夹具对照 | 保留；新增仓库接在同一跟随路径 |
| 受管只读 | 菜单不可用、宿主拒绝、元数据不变 | 保留 |
| Esc／焦点、拖宽、watch 时序、完整视觉 | 未运行窗口、部分无自动断言 | 仍交 terra 核对，不借本次修复宣称覆盖 |

验证分层不变：worker 先保留机械条件不能拒绝 no-details 的复现、补充编排分类的红绿及完成条件；主控在门禁独立审查后沙箱外跑真实窗口正例与全部指定变异，再新包和 terra，最后用户批准敏感证据后集成。worker 不把模拟检查当成窗口证据。
