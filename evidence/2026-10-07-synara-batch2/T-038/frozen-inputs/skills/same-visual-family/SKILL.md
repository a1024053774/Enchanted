# 同一视觉族，不要拼装

v1.2。「视觉族」只是简称：这些块能不能共处。不负责选样子、不负责写文案。若已安装 `frontend-less-ai-tone`，样子交给它；没安装时沿用项目已有品牌/主题，不要在这里另起审美方向。

核心只有一句：先继承（或补一张族卡），再装块。带皮的 Header / Hero / Footer 不能原样嵌进来。无样式 primitives 可以。来源不同不自动违规，来源相同不自动合格；看的是装完之后还剩不剩另一套皮。

## 何时用

多来源拼接；用户要搬参考站区块；已经拼完、每块单看能用但放一起不像一家。

单模板里改文案、解释「什么是视觉族」，不要用。单组件内部修改、且不涉及它与其他区块的视觉关系时，也不要用。用户要把某一块改得跟整页一致时要用。不要把本 Skill 名称写进用户可见选项。

## 先继承，不要重定方向

已有品牌规范、主题或组件体系时，沿用它。局部修改不重新定族。

已选样子但没有成文基准时，从该样子的实际渲染或代码里抄一张 6 行族卡：具体色值、具体字体名、具体圆角像素，不要用「暖灰」「小圆角」这类形容词代替。不要写记忆点、不要写文案。方向尚未确定时，交回选样子的任务，不要在这里自选颜色和字体：

- 底
- 字
- 强调（一条品牌色；`success` / `danger` / `warning` 不算第二条）
- 边线
- 字体栈
- 圆角

一致性以**当前品牌、主题和这一界面**为单位。营销页和工作台可以密度不同；白标按当前租户主题看。不要求整个产品处处同值。

## 怎么装

1. 记下当前体系（已有规范，或上面那张 6 行卡）。
2. 列出这一界面需要的模块。
3. 已有模块：显隐或沿用。外来模块：可以借结构，必须把皮换成当前体系。
4. 缺的东西按类处理，不要为了参考站清单补一整区：
   - **缺事实或案例**：记内容缺口。不编、不拿外站图顶上。正式页按产品决定隐藏还是空状态，不要默认印「待补充」。
   - **用户点名要这块、内容够、当前体系能做**：用当前 token 做结构。
   - **当前载体做不到**（只许改槽位、没有这种模块）：记能力缺口。不擅自扩模板，不搬带皮区块充数。

## 借结构，不借皮

可以借分栏、手风琴、步骤、表单分区。借完必须满足：

- 原 kit 的皮肤规则不再控制该区块；复制进内联 CSS 也算残留
- 仅保留布局或行为规则（栅格、焦点、开合）不算借皮
- 能截图就截图比对实际渲染；纯文本环境逐条比对 token 和计算后的样式值。两种都不只看 CSS 变量名改没改

某一区域仍被另一套品牌字体、品牌强调色、圆角刻度、装饰图、阴影或动效控制，就是借了皮。

真实产品照片不是拼装；未适配的带皮区块才是。许可另判。

## Agent 否决

可以否决：

- 未改皮就嵌了带皮 Header / Hero / Footer
- 导航、主体、页脚里，**同一角色**（主按钮、标题字栈、卡片圆角）各跟一套仍生效的皮肤规则
- 借来的块仍被原 kit 的皮肤规则控制（复制进 `<style>` 也算）

否决时指出具体区块违反了哪条既有规则或族卡约定。其中已定义的状态、反色和组件变体不算另一套皮。样本注释写着「四套 / 三套 kit」本身不是否决证据。

不要用这些当硬门槛：全页字体种数、全页圆角种数、「拿掉公司名还像同一家吗」。后一句留给人看。标题/正文两种字、按钮和卡片不同圆角，只要角色稳定，不算拼装。

## 例外

- 用户明确要拼贴或情绪板：允许，但组合规则要写明，不是误贴
- 多品牌白标：壳跟母品牌、内容跟当前租户主题
- 邮件：客户端能活下来的那部分 CSS 优先，不按完整站点族卡苛求
- shadcn 等带默认皮的组件：换成项目 token 算同族；带着默认 zinc 皮去配另一套首屏算拼装
- 地图、支付等第三方嵌入：圈成外来物，不假装是本族组件
- 设计系统文档、Storybook、组件库展示页：本来就要并排展示多主题/多品牌，不算拼装

## 不要做

- 不要在这里选样子或改文案方向
- 不要按 git 来源一刀切（外来已适配 ≠ 违规；同 kit 未统一 ≠ 合格）
- 不要为填模块清单发明一整区
- 不要用本规则或模型自评当美观通过
