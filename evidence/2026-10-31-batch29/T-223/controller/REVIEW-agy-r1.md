### 2. 夏令时规则与边界判断

- **注释、README 与代码行为的一致性**：
  - 代码注释（[retrospective.ts:59-61](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/retrospective.ts#L59-L61)）：
    > `// Select the calendar date before applying wall time, including when stepping back a week.`
    > `// ECMAScript UTC(t) uses the pre-transition offset for gaps (advance by the gap) and the`
    > `// earlier instant for overlaps. Reapply the requested time so a normalized gap cannot carry over.`
  - 文档（[README.md:1186-1188](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/README.md#L1186-L1188)）：
    > `定期复盘按后台的本地日历日期和墙钟时刻计算，取当前时刻之前或恰好到点的最近一次日程；本周未到点时取上周。`
    > `夏令时规则遵循 [ECMAScript 的 UTC(t)](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-utc-t)：目标日期上的墙钟时刻不存在时，按转换前的偏移解释，向前顺延跳过的时长；时刻重复时，取较早的一次。`
    > `例如 America/New_York 的 2026-03-08 02:30 顺延为 03:30 EDT（07:30Z），2026-11-01 01:30 取第一次 EDT（05:30Z）。同一项目已记录的 scheduled_for 按完整 ISO 时刻去重。`
  - 一致性：JavaScript 原生 `Date.prototype.setHours` 内部通过 ECMAScript `UTC(t)` 将目标日历日期与请求墙钟时刻合成为 UTC 时间戳，在跳过的空白时段采用转换前偏移（顺延跳过时长），在回拨重叠时段取较早一次候选时刻，与注释和 README 完全一致。
- **边界判断（`new Date(now)` 先带着“查询时刻的墙钟时间”经 `setDate` 落到目标日期，若该时间在目标日期不存在，是否会被规范到别的日期，导致随后的 `setHours` 落在错误的一天）**：
  1. **过程推导**：`const slot = new Date(now)`（[retrospective.ts:58](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/retrospective.ts#L58)）保留了 `now` 的墙钟时间 $T_{\text{now}}$。执行 `slot.setDate(...)`（[retrospective.ts:62](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/retrospective.ts#L62) 或 [retrospective.ts:65](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/retrospective.ts#L65)）时，ECMAScript 以目标日历日期 $D_{\text{target}}$ 和原墙钟时刻 $T_{\text{now}}$ 调用 `UTC(t)`。如果 $T_{\text{now}}$ 在 $D_{\text{target}}$ 上不存在（落在跳过窗口内），`UTC(t)` 会将其向后顺延跳过时长 $\Delta_{\text{gap}}$，得到 $T_{\text{now}} + \Delta_{\text{gap}}$。要让顺延后的本地日期跨过午夜变成 $D_{\text{target}} + 1$，当且仅当 $T_{\text{now}} + \Delta_{\text{gap}} \ge \text{24:00:00.000}$。
  2. **在 `America/New_York` 下会不会发生**：**不会发生。** `America/New_York` 的春季夏令时跳过固定在周日凌晨 `02:00`（`02:00 EST` 跳至 `03:00 EDT`，跳过窗口为 `02:00:00.000`～`02:59:59.999`）。即使查询时刻 `now` 的墙钟时间 $T_{\text{now}}$ 落在 `02:00`～`02:59:59.999` 且目标日 $D_{\text{target}}$ 是春季跳过日，`setDate` 顺延 1 小时后也只是同一天（$D_{\text{target}}$）的 `03:00`～`03:59:59.999 EDT`，不会跨过午夜 `24:00`；紧接着执行的 `slot.setHours(schedule.hour, schedule.minute, 0, 0)`（[retrospective.ts:63](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/retrospective.ts#L63)、[retrospective.ts:66](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/retrospective.ts#L66)）会直接覆盖该临时小时与分钟，日期仍停留在正确的 $D_{\text{target}}$。（即便是 `00:00` 跳至 `01:00` 的时区，顺延后也只到当天 `01:xx`，同样不跨日。）
  3. **在别的时区会不会发生**：**理论上仅在“当日末尾跨午夜跳过（如 `23:00` 跳至次日 `00:00`）”或“整日跳过（国际日期变更线变更）”的时区会发生。** 若某时区在 $D_{\text{target}}$ 的 `23:00` 直接跳到 $D_{\text{target}} + 1$ 的 `00:00`（`23:00`～`23:59:59.999` 在 $D_{\text{target}}$ 上不存在），且查询时刻 `now`（在之后某天）的墙钟时刻恰好在 `23:00`～`23:59:59.999` 之间，则 `slot.setDate(...)` 会把 $(D_{\text{target}}, \text{23:xx})$ 规范成 $D_{\text{target}} + 1$ 的 `00:xx`，随后的 `slot.setHours(schedule.hour, schedule.minute, 0, 0)` 就会落在 $D_{\text{target}} + 1$（晚一天）。
  4. **影响多大、是否阻塞本票**：**影响极小，不阻塞本票（非阻塞）。** 一方面现行主流夏令时时区（含 `America/New_York`、欧洲、大洋洲及 `00:00 -> 01:00` 跳过的美洲时区）均不在 `23:00 -> 00:00` 跨日跳过；另一方面后台每 60 秒执行一次 `retrospectiveTick(new Date())`（[daemon.ts:118-120](file:///Users/luckye/Documents/Code/a2a-review/T-223-r1/candidate/workbench/src/daemon.ts#L118-L120)），在目标日当天到点时早已触发并记入 `retrospective_runs`，无须等到数日后的 `23:xx` 才首次计算。
