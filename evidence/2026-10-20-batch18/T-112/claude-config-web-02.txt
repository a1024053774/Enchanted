L595: Choose an effort level
L596: 
L597: Each level trades token spend against capability. The default suits most coding tasks; adjust when you want a different balance.
L598: Level  | When to use it
L599: --- | ---
L600: `low`  | Quick exchanges where you review each result, such as brainstorming, a first sketch, or a small change like a rename
L601: `medium`  | The default on Opus 5.5, Sonnet 5.5, and Haiku 5.5. On Opus 5.5 and Sonnet 5.5, it fits day-to-day engineering work with a clear scope, such as implementing a new feature. On models with a higher default, reduces token usage for cost-sensitive work that can trade off some intelligence
L602: `high`  | Work where verification matters or edge cases are likely, such as fixing a bug in an existing codebase. The default on every model except Opus 5.5, Sonnet 5.5, Haiku 5.5, and Opus 4.7
L603: `xhigh`  | Deeper reasoning at higher token spend. The default on Opus 4.7
L604: `max`  | Hard problems you want Claude to work through without you, such as finding security vulnerabilities. `max` may show diminishing returns and is prone to overthinking, so test before adopting it broadly
L605: `ultracode`  | A Claude Code setting rather than a level: plans a cite138†dynamic workflow for each substantive task at any effort level
L606: In tests on Opus 5.5 and Fable 5.1, Claude at a higher level tested more edge cases and verified more of its work before answering. It also made more choices on its own. At a lower level, Claude returned a starting point sooner, which fits work where you review each result and steer the next step. To see the same tasks run at each level, read cite142†Using Claude Code: Spending your effort†claude.dev on the blog.
L607: The effort scale is calibrated per model, so the same level name does not represent the same underlying value across models. Opus 5.5 cite33†defaults to `medium` , one level below Opus 5’s default of `high`. In Anthropic’s testing, Opus 5.5 at `medium` matches or exceeds Opus 5 at `high` on coding and knowledge-work evaluations. At a given level, Opus 5.5 tends to think more per turn than Opus 5. When you move from Opus 5 to Opus 5.5, start at `medium` rather than carrying over the level you used on Opus 5.
L608: To test levels against your own work, see cite143†Calibrate effort†platform.claude.com in the Opus 5.5 prompting guide.

L43: Fast mode is supported on Opus 5.5, Opus 5, and Opus 4.8. It is not available on Sonnet, Haiku, or other models. Opus 4.7 doesn’t support fast mode, so switching to it turns fast mode off. Fast mode for Opus 4.7 was deprecated on June 25, 2026, and removed on July 24, 2026. What to know:
L44:   * Use `/fast` to toggle on fast mode in the Claude Code CLI. The cite6†VS Code extension offers a Toggle fast mode command when the selected model supports fast mode. Claude Code saves that toggle to your cite7†`fastMode` setting .
L45:   * Fast mode pricing per MTok input/output is $8/$40 on Opus 5.5 and $10/$50 on Opus 5 and Opus 4.8.
L46:   * Available to Claude Code users on subscription plans (Pro/Max/Team/Enterprise) and on Claude Console. Team and Enterprise organizations need an Owner to enable it first, and Console organizations need access provisioned first, both described under cite8†Requirements .
L47:   * For Claude Code users on subscription plans (Pro/Max/Team/Enterprise), fast mode is available via usage credits only and not included in the subscription rate limits.

L52: Toggle fast mode
L53: 
L54: In the CLI, toggle fast mode in either of these ways:
L55:   * Run `/fast`, press Space to toggle on or off, then press Enter to confirm
L56:   * Set `"fastMode": true` in your cite9†user settings file L57: By default, fast mode you turn on in an interactive session persists across sessions. You can configure fast mode to reset each session. See cite10†require per-session opt-in for details. Outside a cite11†cloud session , in cite12†non-interactive mode with the `-p` flag, `/fast` works only in a session launched with fast mode in its cite13†`--settings` value, for example `claude -p --settings '{"fastMode": true}'`; the toggle then applies to that session only and isn’t saved as your default.
L58: The `-p` form requires Claude Code v2.1.205 or later. Elsewhere in non-interactive mode, the command reports that fast mode isn’t available. You can run `/fast` while Claude is working, and Claude Code toggles fast mode without waiting for the turn to end. Claude Code finishes the running turn at its original speed, so the speed change takes effect from your next turn.
L59: If your current model doesn’t support fast mode, turning it on also switches your model, and Claude Code uses the new model from its next request in that turn. For the best cost efficiency, enable fast mode at the start of a session rather than switching mid-conversation. See cite14†understand the cost tradeoff for details. When you enable fast mode:
L60:   * If your current model doesn’t support fast mode, Claude Code switches to Opus
L61:   * You’ll see a confirmation message: “Fast mode ON”
L62:   * A small `↯` icon appears next to the prompt while fast mode is active
L63:   * Run `/fast` again at any time to check whether fast mode is on or off
L64: Opus 5.5 is the fast mode default in Claude Code v2.1.280 and later. Before v2.1.280, fast mode defaulted to Opus 5 from v2.1.219, and to Opus 4.8 on v2.1.154 through v2.1.218. When you disable fast mode with `/fast` again, you remain on Opus. To switch to a different model, use `/model`.
