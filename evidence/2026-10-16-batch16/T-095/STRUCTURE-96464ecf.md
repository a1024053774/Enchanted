# T-095：Codex 0.163.0 面板机械结构

目标是覆盖两种已观察的异步提问布局，并按结构推广到不同问题数、选项数、选中位置和正文。仍只读绑定 worker 的会话与当前屏幕；不匹配问题语义，不自动回答，不改 Herdr 或配置。已有原件只作回归；主控 #109 追加的 1 个根回合才用于未参与修改的真实验证。

## 来源与证据边界

`ui-structure-source.json` 核对了安装包 `0.163.0-aarch64-apple-darwin` 的版本、二进制内的 `tui/src/bottom_pane/async_questions/{mod,input,state,render}.rs` 路径和控制文案。没有取得或反编译 Rust 渲染实现，不能从字符串推断全部控制流。实际布局来源为 `real-panel-inputs.json`、`real-green-inputs.json` 及其指向的原件；两者分别显示有 / 无 `option N/M` 的控制条。

以下是识别器接受的机械结构，不是对 Codex 全部 UI 分支的支持声明。保留 UI 的缩进、顺序与尾部位置；数值均从读数解析，不固定为 1、3 或某段标题。正文只检查其位于标题区域且非空。

| 形态 | 必须同时具备的标记 | 数值与边界核对 |
| --- | --- | --- |
| 有提示的折叠态 | 紧邻普通输入框之前，连续出现 `• Queued follow-up inputs`、缩进的问题计数 `? N question(s)`、再缩进的 `⇧← to answer`；普通输入框和模型 / 快捷键底栏也完整。前面的 Working 活动行不参与提问判定 | N > 0；单复数一致；与同一原生会话全部 pending 请求的问题总数一致。两份屏幕读数的形态和计数须相同。移除无关活动行不改变面板结论。 |
| 展开态 | 尾行是 `enter submit`、`⌃] skip`、`⇧→ main prompt` 的同一控制条；其前是非空标题区域与唯一选中行 `› N.`，其他可见选项为同缩进层级的编号行 | 无计数提示时，必须看到从 1 开始连续、无重复的完整编号列表，选中编号在列表中。有 `option N/M` 提示时核对 N 与选中行、M 与可见编号；允许该布局只显示选中项。 |
| 展开态前缀 | 标题前可以有当前 Working 行、`• Queued follow-up inputs` 行，或二者依次出现 | 不把前缀当作标题；不接受任意未识别前缀、缺标题、缺选择、重复编号或截断控制条。 |
| 旧原件无专属提示的折叠态 | 完整普通活动结构 + Herdr blocked + 绑定原生日志中完整且未解决的提问 | 仍沿用已确认的原生机械事实判据；单独 `blocked + Working` 不够。 |

UI 必须和绑定原生日志一致。原生 clear 而屏幕仍为面板、问题计数不符、两份屏幕形态不同或原生状态在读屏期间改变时，记录冲突并输出 unknown。未识别的尾部不能回退成普通 working。普通 working 继续要求完整活动结构、Herdr working、原生无 pending。

## 回落的已知限制

`skip-tail-investigation.json` 按原生 UUID 绑定的两份归档逐条核对。红态 40 条、绿态 20 条；最后原生记录都早于展开阶段结束，因此没有 skip 后的同 turn 输出、新 turn 或完成事件。隔离 HOME 已删除，不能补查未保留的尾部，也不查询别的 worker 来替代。

已观察到同 turn 后续输出与模型继续执行可以在问题仍待答时发生，因此它们本身不是解决信号；没有证据证明 turn 完成或新 turn 会机械地清除该 UI 请求。当前只接受关联同 call_id 的正式答案映射作为解决信号。`accepted:true` 是接收回执，不能清除 pending。

所以面板关闭后即使屏幕恢复普通 Working，只要原生仍 pending，就只能证明“不再显示面板”，证明不了“已解决”；继续输出 unknown 并记录来源冲突。此处不新增猜测式清除规则，不把合成解决事件当作真实 skip 的证明。
