# T-036 主控决定（2026-10-07）：恢复测试的进程识别核对

问题：`acceptance/test_recovery_e2e.py` 在注入 SIGKILL 前，用 ps 输出中的 Python 脚本路径确认目标进程；经 `os.execv` 转接后 PID 不变，但命令行变为原生 CLI（`cli.ts`），测试拒绝注入。

判定：批准在证据目录中使用一份验收副本，**只**修改这处目标进程识别。这处核对的作用是防止误杀进程，不是业务断言；改为识别原生 CLI 后保护作用不变。条件：
1. 原 `acceptance/test_recovery_e2e.py` 不改；副本与原文件的完整 diff 存档，diff 只能涉及目标进程识别。
2. 识别不得放宽：仍须同时核对目标 PID 与命令行中门禁 CLI 的入口路径，不能变成"任意进程"或只看 PID。
3. 所有业务断言、预期答案、场景数量不变。
4. 同时保留两份结果：原文件在转接入口下的运行结果（因该识别核对而拒绝注入），以及副本的运行结果；红态、绿态和反例（去掉 fence 校验、忽略 Git 回读）都用同一份副本运行。
5. 独立审查须逐行核对这份 diff，并在审查结论中写明。
6. 若副本之外还需要别的修改，停下再问。
