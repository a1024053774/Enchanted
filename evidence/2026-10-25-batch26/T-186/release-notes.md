Enchanted 0.1.4：状态如实、侧栏与流程页按项目收拢、主控开局就知道怎么用 a2a。这一版修的是 0.1.3 真实使用中发现的问题。

- 状态：窗格头和侧栏用同一个状态，不再出现主控回合已结束却一直转圈的情况。已结束的会话显示“结束 N 分”。有 worker 在等主控答复、而主控不在回合中时，项目行显示“等你处理”。
- 没接入的会话：用绝对路径或别名启动 claude、codex，会绕过 Enchanted 的包装脚本，这样的会话没有插件和钩子。现在窗格会提示“这个会话没接入 Enchanted”，状态显示“未知”，不再显示假的“运行中”。直接敲 `claude` 或 `codex` 启动即可接入。
- 权限弹窗：终端里的程序启动后 6 秒没有任何输出时，窗格提示它可能在等 macOS 的权限弹窗（例如访问“文稿”），弹窗可能被其他窗口挡住了。
- 终端显示：改用 WebGL 渲染器并启用 Unicode 11 宽度表，中文不再多出空隙，表格边框对齐，powerline 分隔符正常显示；设置里可以改终端字体。按深色背景配色的文字（例如 Claude Code 问答框的正文）在浅色终端里会自动调深，不再是一片空白。
- 侧栏：已结束的会话和被新 attempt 取代的会话折进“历史 N 个”，默认收起；“清理”把已结束的会话从列表拿掉，记录不删；已集成、仍空闲的 worker 显示“回收”。启动时打开最近活跃、未结束的会话。
- 流程页：本项目的任务排在前面，其他项目的任务收进默认收起的分组；标题不再重复成“T-1 · T-1”。
- 门禁回执：worker 窗格里不再打印整段 JSON，改为三四行中文摘要；完整内容在记录页新增的“门禁回执”一节。
- 工作分支：主控建任务时没指定分支，后台自动用“前缀 + 项目名”（默认 `enchanted/`），并在回执里写明，不再停下来问；前缀可在设置里改。被门禁拒绝的建任务请求不会留下新建的分支。
- 主控开局说明：项目终端里的 Claude Code 和 Codex 在会话开始时都会收到几行说明：`a2a` 已在 PATH 上；用户要它当主控时直接运行 `a2a request`，不要先用问答框问。主控说明还补了几条：验收脚本只用相对路径、不写 sleep 轮询、并行任务的共用约定写进每张卡。

升级提醒：

- Codex 用户：新版在你自己的 Codex 里第一次启动时，Codex 会弹一次钩子信任框（Enchanted 新加了一个开局钩子），需要你本人确认一次。Enchanted 不写你的 Codex 配置。

已知限制：

- 应用内主控写的完成条件仍可能偏弱或写错；门禁会如实拒收，需要主控修卡重派。
- “没接入”提示只认出直接以 `claude`、`codex` 为程序名启动的进程；以 `node …/cli.js` 方式启动的不会被认出，也不会提示。
- “启动即失败可回收”只在模拟的启动失败上验证过。
- 只支持 macOS（Apple 芯片）；CLI 只支持 Claude Code 与 Codex。

安装包适用于 macOS arm64（Apple Silicon）。解压后将 `Enchanted.app` 放入“应用程序”。

本包使用 ad-hoc 签名，未经 Apple 公证。首次打开如被系统拦截，可在访达中右键选择“打开”；必要时运行：

```sh
xattr -dr com.apple.quarantine /Applications/Enchanted.app
```

使用前先安装并登录官方 Claude Code 或 Codex。bundle id 与后台数据目录保持不变。
