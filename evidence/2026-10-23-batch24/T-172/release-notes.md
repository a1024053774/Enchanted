Enchanted 0.1.3：多视图与分屏、工作中输入不再打断交付、修订重派与回收补齐。

- 视图：项目、任务、agent 三种视图，可在终端间切换；任务视图可以在 worker 旁并排开一个普通终端，它不算 worker、不占任务路径，在里面打字也不记为人工介入。
- 项目额外目录：在项目行右键“编辑项目”里添加或移除额外目录，此后启动的 worker 可以写这些目录；这些改动不进门禁的审查与集成，也没有 worktree 隔离。受管会话可以联网，并沿用你自己的 Codex 配置与 MCP；写入范围仍是硬边界。
- 输入法：在一行中间用输入法插入的文字，就是你打的字（有无辅助功能读屏都一样）。
- 终端：只读窗格按 CLI 自己的尺寸显示，不再出现重叠的文字；终端协议回报不再被记成你的输入。
- 工作中输入：worker 正在工作时你在它的窗格里打字，会排队或并入当前回合，原来的交付不会因此失效，窗格也不会停在等待。
- 流程页、侧栏与 Reflect：用同一份会话状态，已结束的会话保留显示；流程页按派发分出执行主控的泳道。
- 记录与指标：你批准或拒绝角色申请记为你的输入；指标页标出没覆盖到、数不清的主控回合及其来源。
- 审查员：要求只输出 JSON；格式不对的输出保留原文，可以为同一次交付新开一个干净的审查会话。
- Codex：受管会话里不再弹出会吞掉回执回车的额度提示；提交后迟迟没开始的回合会标出来。
- 修订与重派：`a2a help` 与角色说明写明“保存新卡 → revise → 回收旧 attempt → 派发”；CLI 启动即失败、没建起会话的 attempt 现在可以回收；被修订作废的 attempt 留下的问题标为“可能已随修订失效”，不再计入等你决定，由你确认后一键关闭。
- 只读视图不抢输入焦点；窗格标题显示已确认的主控角色；获批的主控可以开普通项目终端。

已知限制：

- 应用内主控写的完成条件仍可能偏弱或写错（真实使用中出现过，门禁会如实拒收，需要主控修卡重派），主控说明已补自检步骤，但没有消除。
- “启动即失败可回收”只在模拟的启动失败上验证过，没在真实 Codex 启动失败时复验。
- 只支持 macOS（Apple 芯片）；CLI 只支持 Claude Code 与 Codex。

安装包适用于 macOS arm64（Apple Silicon）。解压后将 `Enchanted.app` 放入“应用程序”。

本包使用 ad-hoc 签名，未经 Apple 公证。首次打开如被系统拦截，可在访达中右键选择“打开”；必要时运行：

```sh
xattr -dr com.apple.quarantine /Applications/Enchanted.app
```

使用前先安装并登录官方 Claude Code 或 Codex。bundle id 与后台数据目录保持不变。
