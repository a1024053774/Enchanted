Enchanted

让 Claude Code 和 Codex 在同一个桌面工作台里分工干活。谁在做哪张票、交上来的是哪个提交、检查和审查过没过，都由门禁记下来，不靠模型自己说“做完了”。

a2a 是 Enchanted 的编排内核。目前是开发中的初版，只支持 macOS，CLI 只支持 Claude Code 与 Codex，用的是你本机已经登录的官方 CLI。

点一点工作台

下面是照着真实工作台还原的界面。数据是虚构的：不连后台，不调用模型，终端里的输出是预先写好的。工作台目前只有深色主题，所以演示窗口不随本页切换浅色。

  1. 右上角有一条黄色通知：构思主控在等你回答。点它，或点侧栏里标黄的构思主控，在提问面板里选一个选项，再点“发送答复到窗格”。
  2. 在任意窗格上点右键，或点窗格标题栏的“⋯”：可以分屏、放大、重命名、关闭，或者把右键转给窗格里的程序。
  3. 切到“流程”标签：一张票一条泳道，能看到打回线，还能展开“还有 N 个”。
  4. 侧栏里点别的项目或 agent，再点三角折叠层级，看汇总状态。

窗口按桌面尺寸还原，在手机上请左右滑动查看。

可点击的演示需要 JavaScript。启用后，这里会出现还原的工作台窗口，包括：

  • 侧栏：三个虚构项目（分支与领先、落后提交数），以及按“构思主控 → 执行主控 → worker、审查员、监视器”缩进的 agent 树，七种状态都有；
  • 终端页：任务条、按分屏排列的窗格、窗格菜单、提问面板、门禁状态栏；
  • 右上角的应用内通知和 Dock 角标；
  • 流程页：每张票一条泳道、五个阶段、打回线和“还有 N 个”。

状态图标：● 运行中　◐ 等待用户回答　◑ 等待主控回答　○ 空闲　✓ 已结束　◌ 未恢复　? 未知。识别不出状态时显示“未知”，不往“运行中”或“空闲”上猜。

为什么要门禁

几个 agent 一起干活时，常见的做法是把规矩写进提示词：先认领再动手，别改测试，做完找人审。对话一长，这些规矩就容易被忘掉；模型说“完成了”，也不等于真的完成。

Enchanted 的做法是：能机械核对的事交给脚本和门禁，提示词只写需要判断的部分。门禁拒收的交付不会进工作分支，拒收原因会写回给原来的 worker。

一张票怎么走完

派出去的活都是受管任务，挂一张任务卡：目标、非目标、允许修改的路径、完成条件，以及验收文件（完成条件依赖的测试、脚本和夹具）。之后每一步都经过同一个门禁入口。

  1. 认领门禁确认谁是这张票当前的执行者，并给这次执行一个 attempt。旧 attempt 交上来的东西一律拒收。
  2. 交付worker 显式交出一个提交号。在对话里说“做好了”不算交付。
  3. 机械检查核对身份与版本、修改有没有越出允许的路径、验收文件有没有被改、完成条件命令、红态、规则式检查和提交尾注。任何一项不过，就打回给原 worker，打回次数有上限。
  4. 独立审查每次交付都新开一个审查会话。它在一次性的候选副本里工作，断网，碰不到 worker 的工作区；要检查完成条件够不够格，并做变异检查。
  5. 集成全部通过后，才合进项目的工作分支。Enchanted 不替你 push。
写审分开
写代码的会话和审代码的会话不是同一个，审查会话只为这一次交付存在。
提示词管判断，脚本管事实
路径、提交号、尾注这些能核对的，由门禁核对；角色卡只写“用哪个命令”。没有策略引擎。
门禁不是安全沙箱
它约束的是同一个用户下互相信任的协作者，按流程拦住越界的交付。worktree 和会话身份不能当作安全隔离。

两层主控

你日常只需要和构思主控说话。下面的层级就是演示侧栏里 agent 树的缩进方式，层级只来自启动记录，不从窗格标题或终端文字猜。

  • 你
    • 构思主控接想法、问清楚、写决定和任务卡、标就绪、转述完成报告。不直接派发 worker。
      • 执行主控派发、盯进度、验收、集成、回收，全部经门禁。自己不写代码。
        • worker只在分到的任务和 attempt 里写代码。
        • 审查员每次交付新开一个，只读。
        • 监视器只读观察、记录、报警，不能宣布成功。

主控和 agent 发出的提示词不算你的输入。你在 worker 的窗格里直接打字，会记成一次人工介入。

现在能用的

工作台

  • Claude Code 和 Codex 跑在交互终端里，终端由常驻的编排后台托管；关掉窗口，agent 继续跑。
  • 侧栏列出项目目录，显示当前分支和相对上游的领先、落后提交数。
  • agent 树按层级缩进，有七种状态；折叠后父项显示子会话的状态汇总，等你回答的最醒目。
  • 随时开普通 zsh 窗格；窗格可以向右或向下分屏、放大、重命名、关闭，可以把右键转给窗格里的程序；布局重开后恢复。
  • agent 用原生提问工具问你时，侧栏标黄，可以在界面里点选项作答，答复写回原来的终端；多选题和无法核实的提问仍回原终端里答。
  • 有会话等你回答时弹出应用内通知，应用在后台时显示 Dock 角标，两者可以分别关掉；不调用系统通知。
  • 流程页：一张票一条泳道，阶段取自门禁记录，显示打回次数和每个阶段里的 agent。
  • 在界面里新建项目和任务（简化表单，注册时走任务卡校验）。
  • 退出应用不结束会话；重新打开时恢复之前打开的窗格和分屏布局。
  • 打包成可以双击打开的 macOS 应用。

门禁与记录

  • 任务卡由命令生成和校验。
  • 验收文件受保护：候选改到它们就拒收。
  • 审查在一次性候选副本里做，要求检查完成条件并做变异检查。
  • worktree 统一命名、干净时自动清理；合并冲突写回 worker 处理，程序不替你取舍。
  • agent 的每个提交自动带上提交尾注：任务、attempt、角色、工具、模型、思考强度和启动记录号，门禁会和启动记录核对。
  • 每个 attempt 结束时记一次验收打分：结果，以及边界纪律、工程品味各 0–3 分。

即将

  • 模型和思考强度不再写死：在设置里按角色修改，主控派发时也可以指定。开发中

已知限制

  • 只支持 macOS，安装包为 Apple 芯片（arm64）构建；CLI 只支持 Claude Code 与 Codex，需要你本机已经安装并登录。
  • 安装包是 ad-hoc 签名，没有经过 Apple 公证。
  • 这是开发中的初版。项目作者自己的日常派发还没有切换到它上面，切换条件写在仓库的 intent.md 里。
  • 编排后台重启后，用正常登录方式启动的主控不会自动续接，worker 窗格也不会恢复执行，都显示“未恢复”，由执行主控按中断恢复流程处理。
  • 没有做过可靠性、吞吐或成本方面的对照实验，本页不做这类承诺。

下载与安装

安装包发布在 GitHub Releases，是一个 .zip，解压后把 Enchanted.app 拖进“应用程序”。

因为没有公证，第一次打开时 macOS 会拦下。在 Finder 里右键点应用，选“打开”；或者在终端里解除隔离：

xattr -dr com.apple.quarantine /Applications/Enchanted.app

使用前，先在本机装好并登录官方的 Claude Code 或 Codex。Enchanted 不写你的 ~/.claude、~/.codex 全局配置，每个会话的权限和钩子都通过启动参数传入。

从源码构建和运行的说明见仓库里的 工作台说明。
