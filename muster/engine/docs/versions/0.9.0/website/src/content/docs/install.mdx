---
title: Install Muster
description: Install, update, and verify Muster on Linux, macOS, and Windows.
---

Muster publishes stable-channel binaries for Linux, macOS, and Windows. Windows is generally available, with documented platform-specific limitations and ongoing fixes.

## Install

On Linux or macOS, run:

```bash
curl -fsSL https://muster.dev/install.sh | sh
```

On Windows, run:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://muster.dev/install.ps1 | iex"
```

If endpoint security blocks that fileless PowerShell command, open Command Prompt and run:

```cmd
curl.exe -fsSLo install.cmd https://muster.dev/install.cmd && install.cmd && del install.cmd
```

The installer downloads the release binary for your platform and places it on your PATH. New direct installs use the stable update channel. Existing Windows preview installs stay on preview until you switch them with `muster channel set stable`. On Windows, PATH points to the active versioned release directory; the installer also updates the `current` and stable `bin` compatibility aliases, so updates do not need to overwrite a running `muster.exe`.

## Install with Homebrew

If you already use Homebrew:

```bash
brew install muster
```

## Install with mise

If you already use mise:

```bash
mise use -g muster
```

If mise reports `muster not found in mise tool registry`, update mise and retry. Older mise versions predate the Muster registry entry; `mise use -g github:musterdev/muster` works as a temporary fallback.

## Install with Nix

If you already use Nix, Muster provides a flake that builds Muster from source:

```bash
nix run github:musterdev/muster/v0.x.y
nix build github:musterdev/muster/v0.x.y
nix profile install github:musterdev/muster/v0.x.y
```

Replace `v0.x.y` with the latest release tag. You can omit the tag to track `master`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:musterdev/muster
```

Use the same Nix workflow to update Muster. For a profile install, list your profile entries and upgrade the Muster entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Muster is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update muster
```

## Download manually

You can also download a binary from [GitHub releases](https://github.com/musterdev/muster/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `muster-linux-x86_64` |
| Linux aarch64 | `muster-linux-aarch64` |
| macOS Intel | `muster-macos-x86_64` |
| macOS Apple silicon | `muster-macos-aarch64` |
| Windows x86_64 | `muster-windows-x86_64.zip` |

On Linux or macOS, make it executable and move it somewhere on your PATH.

```bash
chmod +x muster-linux-x86_64
mv muster-linux-x86_64 ~/.local/bin/muster
```

### Windows archive

Stable releases and preview prereleases both include `muster-windows-x86_64.zip`. The archive contains `muster.exe` and its app-local ConPTY runtime. Keep the extracted directory together; do not copy only `muster.exe`.

## Verify

Start Muster:

```bash
muster
```

If your shell cannot find `muster`, restart the terminal or check that the install directory is on your PATH.

## Update

Muster checks for new releases and notifies you in the app. You can update manually:

```bash
muster update
```

Use `muster update` only for installs managed by Muster's own installer. Update Homebrew, mise, and Nix installs through those package managers instead.

Direct installs on Linux, macOS, and Windows use the stable update channel by default. To opt into preview builds from `master`, set the channel:

```bash
muster channel set preview
```

Switch a direct install back to stable the same way:

```bash
muster channel set stable
```

For direct installs, changing channels checks the selected channel and installs its latest binary. If that update fails, run `muster update` to retry from the configured channel.

Preview builds are regularly published GitHub prereleases from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Homebrew, mise, and Nix installs do not use the preview channel.

Stable is the recommended channel for normal Windows use. Preview receives fixes sooner but can regress, so opt in only when you want that tradeoff. Existing Windows preview installs remain on preview until you switch them explicitly. If an older preview build rejects `muster channel set stable`, run `muster update` once on preview, then retry the channel switch.

By default, `muster update` installs the new binary and leaves endpoint-generation-1 servers and their pane processes running. Start Muster again to reconnect with the updated client. Client-only changes work immediately. A new server-side action stays unavailable until that server is updated and restarted; the client shows a notice instead of disconnecting. Servers from before endpoint generation 1 need one final stop during update.

To opt into experimental live server handoff for supported running sessions, run:

```bash
muster update --handoff
```

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then run Muster again to reconnect with the updated client. The compatible old server keeps running. Restart it later with `muster server stop` or `muster session stop <name>` only when you want server-side changes from the new release.

## Requirements

Stable-channel binaries are available for Linux, macOS, and Windows x86_64. See [Windows support](/docs/windows-beta/) for supported workflows and known limitations. Windows ARM64 runs the x86_64 build under Windows emulation.
