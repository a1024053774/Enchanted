---
title: Persistence and remote access
description: Detach from Muster, reattach later, use named sessions, and connect over SSH.
---

Muster keeps panes running in a background server. Your terminal client can detach and reconnect later.

For the local, SSH, and `muster --remote` workflows, see [How to work with Muster](/docs/how-to-work/).

## Detach and reattach

Start Muster:

```bash
muster
```

Detach the client with `ctrl+b q`.

Your panes and agents keep running. Reattach by running Muster again:

```bash
muster
```

If you want to end the session and stop its panes, stop the default server:

```bash
muster server stop
```

## Named sessions

Use named sessions when you want independent Muster servers.

```bash
muster session list
muster session attach work
muster session attach side-project
muster session stop work
muster session delete side-project
```

A named session has its own panes, tabs, workspaces, sockets, and runtime state. It still shares the same global config file.

Use `--json` for scripts:

```bash
muster session list --json
muster session stop work --json
muster session delete side-project --json
```

## Remote attach over SSH

Run Muster on a server and attach from any SSH client:

```bash
ssh you@server
muster
```

In this mode your shell is remote, Muster runs on the remote host, and panes keep running there after you detach.

You can also attach through SSH from your local machine:

```bash
muster --remote workbox
muster --remote ssh://you@server:2222
```

In this mode your local Muster is a thin client. It connects over SSH, starts or attaches to the remote Muster server, and streams the UI back to your local terminal. Because the client runs locally, Muster can bridge local desktop features such as image clipboard paste into the remote session by copying the image to a remote temp file and pasting that path.

For repeat targets, use your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
muster --remote workbox
```

Remote attach supports Linux and macOS hosts on x86_64 and aarch64. Muster checks the remote platform, prefers a matching `muster` already on the remote `PATH`, then checks `~/.local/bin/muster`. If no matching binary exists, interactive runs prompt to install one to `~/.local/bin/muster`; non-interactive runs fail instead of modifying the host. If `~/.local/bin` is not on the remote `PATH`, Muster warns after install.

If you SSH into the server first and run `muster` there, Muster runs entirely on the server. That mode is useful and simple, but it cannot access your local desktop clipboard beyond normal terminal text paste.

When your local and remote platforms match, Muster can copy the current local binary. Otherwise it downloads the matching release asset from `https://herdr.dev/latest.json`.

For local builds or custom binaries, set `MUSTER_REMOTE_BINARY` to a local file path before running remote attach.

```bash
MUSTER_REMOTE_BINARY=target/release/muster muster --remote workbox
```

## Remote named sessions

Use `--session` with `--remote` to attach to a named session on the remote host:

```bash
muster --remote workbox --session agents
```

## Direct terminal attach

Full Muster attach opens the whole workspace UI. Direct attach opens one server-owned terminal in your current terminal.

Attach by agent target:

```bash
muster agent attach reviewer
```

Attach by terminal ID:

```bash
muster terminal attach term_abc123
```

Direct attach streams the current rendered terminal state, then live ANSI frames. Input goes straight to that terminal.

Detach with `ctrl+b q`. Send a literal `ctrl+b` with `ctrl+b ctrl+b`.

Only one writable direct attach client owns input and resize for a terminal. Use `--takeover` to replace an existing owner:

```bash
muster terminal attach term_abc123 --takeover
```

## Single-process escape hatch

Use `--no-session` to run Muster without the background server/client split:

```bash
muster --no-session
```

This is mainly an escape hatch for debugging or compatibility. The default persistent session mode is the normal path.
