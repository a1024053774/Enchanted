---
title: CLI reference
description: Muster commands for sessions, workspaces, tabs, panes, agents, waits, integrations, and status.
---

Muster’s CLI talks to the running server over the same local socket API used by integrations and agents.

Most commands print JSON responses. Use them from scripts when you want deterministic automation.

## Launch and status

```bash
muster                         # launch or attach to the default session
muster --session work          # launch or attach to a named session
muster --remote workbox        # attach through SSH, using local keybindings
muster --remote workbox --remote-keybindings server
muster --no-session            # single-process escape hatch
muster --default-config        # print default config
muster update                  # download and install the latest version
muster --version               # print version
```

Status commands:

```bash
muster status
muster status server
muster status client
```

## Server

```bash
muster server
muster server stop
muster server reload-config
```

`muster server` runs the headless server explicitly. Use it for supervised or service-style setups. `reload-config` applies reloadable settings without restarting panes.

## Sessions

```bash
muster session list [--json]
muster session attach <name>
muster session stop <name> [--json]
muster session delete <name> [--json]
```

Use `default` as the session name when you need to stop the default session explicitly.

## Workspaces

```bash
muster workspace list
muster workspace create [--cwd PATH] [--label TEXT] [--focus] [--no-focus]
muster workspace get <workspace_id>
muster workspace focus <workspace_id>
muster workspace rename <workspace_id> <label>
muster workspace close <workspace_id>
```

Create a workspace without stealing focus:

```bash
muster workspace create --cwd ~/project --label api --no-focus
```

## Worktrees

```bash
muster worktree list [--workspace ID | --cwd PATH] [--json]
muster worktree create [--workspace ID | --cwd PATH] [--branch NAME] [--base REF] [--path PATH] [--label TEXT] [--focus] [--no-focus] [--json]
muster worktree open [--workspace ID | --cwd PATH] (--path PATH | --branch NAME) [--label TEXT] [--focus] [--no-focus] [--json]
muster worktree remove --workspace ID [--force] [--json]
```

Worktrees are normal Muster workspaces with Git checkout provenance. `worktree create` creates a Git worktree checkout, opens it as a workspace, and groups it with the parent repo workspace. Without `--path`, Muster creates the checkout under `<worktrees.directory>/<repo>/<branch-slug>`.

`workspace close` closes Muster state only. `worktree remove` is the explicit checkout deletion path; it runs `git worktree remove`, never deletes the branch, and requires `--force` when Git refuses a dirty checkout.

## Tabs

```bash
muster tab list [--workspace <workspace_id>]
muster tab create [--workspace <workspace_id>] [--cwd PATH] [--label TEXT] [--focus] [--no-focus]
muster tab get <tab_id>
muster tab focus <tab_id>
muster tab rename <tab_id> <label>
muster tab close <tab_id>
```

## Panes

```bash
muster pane list [--workspace <workspace_id>]
muster pane get <pane_id>
muster pane rename <pane_id> <label>|--clear
muster pane split <pane_id> --direction right|down [--cwd PATH] [--focus] [--no-focus]
muster pane close <pane_id>
```

Read output:

```bash
muster pane read <pane_id> [--source visible|recent|recent-unwrapped] [--lines N]
muster pane read <pane_id> --source visible --ansi
muster pane read <pane_id> --source recent-unwrapped --lines 120
```

Send input:

```bash
muster pane send-text <pane_id> <text>
muster pane send-keys <pane_id> <key> [key ...]
muster pane run <pane_id> <command>
```

`pane run` submits text plus Enter atomically. Prefer it over `send-text` plus `send-keys Enter` for commands.

Report agent state from custom hooks:

```bash
muster pane report-agent <pane_id> \
  --source ID \
  --agent LABEL \
  --state idle|working|blocked|unknown \
  [--message TEXT] \
  [--custom-status TEXT] \
  [--seq N]
```

## Agents

```bash
muster agent list
muster agent get <target>
muster agent read <target> [--source visible|recent|recent-unwrapped] [--lines N] [--format text|ansi] [--ansi]
muster agent send <target> <text>
muster agent rename <target> <name>|--clear
muster agent focus <target>
muster agent wait <target> --status <idle|working|blocked|unknown> [--timeout MS]
muster agent attach <target> [--takeover]
muster agent start <name> [--cwd PATH] [--workspace ID] [--tab ID] [--split right|down] [--focus|--no-focus] -- <argv...>
```

Agent targets can be terminal IDs, unique agent names, detected or reported agent labels, or legacy pane IDs. Names and labels are agent identities. Terminal IDs and legacy pane IDs are low-level escape hatches.

`agent read` reads the resolved terminal stream. `agent send` writes literal text to that stream. `agent get`, `agent focus`, `agent wait`, and `agent attach` require the resolved terminal to have agent identity. `agent rename` can assign that identity.

Use `pane send-text`, `pane send-keys`, `pane run`, and `terminal attach` for ordinary terminals, servers, tests, shells, or low-level terminal control. Use `pane run` when you want to submit a command with Enter.

## Direct terminal attach

```bash
muster terminal attach <terminal_id> [--takeover]
```

Detach from direct attach with `ctrl+b q`. Send literal `ctrl+b` with `ctrl+b ctrl+b`.

## Waits

Wait for output in a pane:

```bash
muster wait output <pane_id> --match <text> [--source visible|recent|recent-unwrapped] [--lines N] [--timeout MS] [--regex] [--raw]
```

Wait for pane agent state:

```bash
muster wait agent-status <pane_id> --status <idle|working|blocked|done|unknown> [--timeout MS]
```

Use `wait output` for normal commands and servers. Use `wait agent-status` for coding agents.

## Integrations

```bash
muster integration install pi
muster integration install omp
muster integration install claude
muster integration install codex
muster integration install opencode
muster integration install hermes
muster integration uninstall pi
muster integration uninstall omp
muster integration uninstall claude
muster integration uninstall codex
muster integration uninstall opencode
muster integration uninstall hermes
muster integration status [--outdated-only]
```

## Read sources

| Source | Meaning |
| --- | --- |
| `visible` | Current rendered screen. Best for UI feedback loops. |
| `recent` | Recent scrollback with terminal wrapping. |
| `recent-unwrapped` | Recent scrollback without soft wrapping. Best for logs. |

## Environment variables

| Variable | Purpose |
| --- | --- |
| `MUSTER_CONFIG_PATH` | Override the config file path. |
| `MUSTER_SESSION` | Select a named session for CLI commands. |
| `MUSTER_SOCKET_PATH` | Low-level socket path override. |
| `MUSTER_LOG` | Set log filter, for example `MUSTER_LOG=muster=debug`. |
| `MUSTER_DISABLE_SOUND` | Disable sound playback even when sound notifications are enabled. |
