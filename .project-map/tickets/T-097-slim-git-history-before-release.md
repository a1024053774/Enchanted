## 背景

项目要开源。`evidence/` 约 4.8 GB（T-088 实测，git 跟踪 136,623 个文件），`.git` pack 约 825 MiB。T-088 已决定新批次起证据归档到外置盘，**已提交历史不改写**，"开源前是否瘦身历史"当时留待用户提出。

## 用户已定（逐字，2026-10-17，会话"a2a-构思主控"）

用户说："发布前先瘦身，做完后我使用看看我再提反馈意见。"——发布之前先瘦身历史；顺序是先做完当前功能、用户使用并反馈，之后才发布。

## 本票要定、尚未定的

1. 瘦身范围：哪些历史路径从全部提交里移出（候选：`evidence/` 下的 run/fixtures 目录、`*.tar.gz`、`*.bin`、sqlite、监视器日志，即 T-088 的归档类别），哪些摘要必须保留。
2. 工具与可逆性：改写历史不可逆；先做完整备份（外置盘 bundle 加原仓库只读保留）；改写只在副本里做，核对通过后才替换；**不 push**，push 须用户另行批准。
3. 被移出的内容去向：搬到外置盘归档并在仓库留 `*.archive.json` 清单，还是直接丢弃；引用它们的 ticket/报告的链接如何不悬空。
4. 提交哈希会全部改变：ticket、证据里引用的提交哈希、门禁的提交尾注与 launch 记录如何对应到新哈希（映射表保存在仓库）。
5. 时机：用户使用反馈之后、发布之前；期间新工作不阻塞。

## 完成条件

- [ ] 用户接受上面各项的决定；之后另开 build 票。
