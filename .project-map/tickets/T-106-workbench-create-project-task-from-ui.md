## What to build

来源同 T-105（用户逐字原话见该票）。现状：新建项目、新建任务（14 字段任务卡）、启动主控、派 worker 都只能走 gates CLI；用户首次打开 `/Applications/a2a.app` 只看到"还没有项目"。

用户逐字选项（2026-10-19，会话"a2a-构思主控"，AskUserQuestion）："界面有入口 + 主控代办 (Recommended)"，选项原文："界面上有“新建项目”“新建任务”按钮，只填名字和目标；任务卡的 14 个字段由主控 agent 补全后交你确认。你不用敲任何命令，也可以直接对主控说话让它建。"

1. "新建项目"：选一个现有 git 仓库目录（或让后台 `git init` 一个新的，要用户在界面确认），填名字；后台经**现有门禁命令**注册，界面不另做一套。
2. "新建任务"：只填标题和目标；后台起一个**主控窗格**（Claude Code，沿用 `controller_start` 和 T-093 的正常登录入口，权限与启动参数不变），把"补全任务卡 14 字段"的请求写给主控，主控用门禁命令生成任务卡草稿，**界面展示草稿，用户点确认才注册任务**；用户可编辑后再确认。
3. 用户也可以直接在主控窗格里对主控说"建个项目/任务"，走同一条门禁命令；不新增第二条创建路径。
4. 界面入口随时可用：没有主控窗格时，"新建任务"会先起一个（说明会占用一个 Claude 根回合，需用户点确认）。
5. 提示词管判断、脚本管事实：任务卡字段的合理性由主控和用户判断，门禁只校验格式（缺字段、完成条件不是命令就拒收）。

## Acceptance

- [ ] 红态：当前空库只能走 CLI 建。绿态：真实 Electron 空库 → 新建项目 → 新建任务（填标题和目标）→ 主控出草稿 → 用户确认 → 任务出现在列表，且与 CLI 直接注册的结果一致（同一份库记录）。
- [ ] 反例：草稿未确认前库里没有该任务；门禁拒收的草稿（缺字段）在界面显示拒收原因而不是静默失败；取消确认不留残余。
- [ ] 真实模型回合数照实记录（根回合预算按 manifest 声明）；失败不补称 PASS。
- [ ] 不绕过门禁、不写用户 `~/.claude`；`project_map.py status` 0 问题。

## 不做

不做派 worker 的界面（另票）；不做任务卡模板编辑器；不改门禁校验规则。若"起主控"在界面里需要比薄层更多的新增设计，停下上报。

## 裁定（2026-10-19，改为简化表单）

执行主控 needs-decision：门禁里没有独立的项目记录；主控必须挂在已有任务上；主控没有权限调任务卡和注册命令。用户选项逐字："B 简化表单,不用主控 (Recommended)"，选项原文："界面上放一张简化表单建项目和任务，其余任务卡字段用合理默认值，不叫模型。你马上能用，不动门禁语义；代价是不再“交给 agent”补全任务卡，这一项留到后面再说。"

据此取代上文第 2～4 条：不起主控、不经模型；界面表单只填项目（仓库目录、名字）和任务（标题、目标、完成条件命令），其余字段用合理默认值并在表单里可见、可改；仍只经现有门禁命令注册，不新增第二条创建路径。真实模型回合数为 0。若"项目"在门禁里确实无处安放，以现有门禁已有的最小方式落地（例如项目由首个任务隐含）并照实写明；需要新增门禁语义（如独立项目记录）则停下上报，不就地做。"交给 agent 补全任务卡"记为未做，留作日后另票。
