## What to build

来源：T-107 缺口 2。用户逐字（2026-10-20，执行主控会话，经执行主控转述 `20261020T053124Z-executor-needs-decision-001`）："a2a-构思主控 那边什么都没收到,关于 a.是否可以用 mcp 或者 hook,这种让模型想要发起问题时,让它调用相应的接口在我们的界面上展示出来 b.这种结构要清晰的展示出来[Image #3] 类似于这种,结构层次要清晰. c.这个要做的,不调用系统通知了,只在我们 app 内部通知"

1. **数据**：派发 worker、reviewer、monitor 时，把派发它的主控的 launch 记为父 launch，写进启动记录/派发记录（追加，不改旧记录）；构思主控 → 执行主控的关系同样记录。旧会话没有父记录的，仍显示"未归属"，不回填猜测。
2. **展示**：侧栏 agent 树按父子关系缩进，层次一眼看得清：构思主控 → 执行主控 → worker / 审查员 / 监视器；父子之间有连接线或明显缩进，可折叠；折叠时父项显示子项状态汇总（有等待用户回答的最醒目）。关系不明的进"未归属"。
3. **视觉参考**：用户附了参考图（"类似于这种,结构层次要清晰"），执行主控只收到占位图标，已请用户重发。**先做数据（第 1 条）与基础缩进树**；拿到参考图后再按图对齐视觉，不要凭想象定样式。若 worker 开工时仍没有图，视觉部分另记缺口上报，不阻塞数据部分合入。
