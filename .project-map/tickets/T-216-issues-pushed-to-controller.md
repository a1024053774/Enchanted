## What to build

依据 [T-210](T-210-issues-controller-first.md)。worker、审查员、监视器上报问题时，执行主控马上收到它，并能答复、关闭或交给用户；用户在问题界面看到的“等你决定”只剩主控交给用户的、属于只交用户类别的、以及主控 15 分钟没处理的。

- 上报（含 blocking）即由门禁投给该任务的执行主控：带编号、标题、正文、上报者、是否阻塞，以及主控可用的处置命令。投递记为系统来源，不算用户输入。
- 主控答复送回上报的会话，记为主控的回答（沿用 T-124）；主控可以关闭（附理由，可重开）或交给用户（附理由）。
- 标 blocking 的问题不再一上报就算“等你决定”。
- 执行主控的角色卡与命令说明写明：涉及权限、范围、验收条件、安全、不可逆操作的问题，主控不回答、不关闭，只附理由交给用户。
- 没有在线的执行主控时，投递按收件箱现有规则排队；问题照旧按 15 分钟规则落到用户，不丢。
- 问题界面每条写明是谁处理的（主控答、主控关、交给你、你答），主控已答、已关的不计入“等你决定”。
- 投递进主控终端：四家 CLI（Claude Code、Codex、agy、opencode）走同一条路。编排后台调用私有 hc 的 `terminal.send`，带状态条件，只在主控终端上报可接收状态时送入，状态取 OSC 7501。选目标按已批准角色绑定的终端与项目，不再靠 Claude transcript 匹配，也不再按 CLI 的原生会话号筛选。用户 2026-11-01 回答“T-216 的投递要四家 CLI 统一改走 hc 的 terminal.send 吗？”：“统一走 hc”。
  - 固定版本 hc 0.1.15 的条件能力（第四轮实测，[RPC 返回](../../evidence/2026-10-31-batch29/T-216/round4-hc-probe-01.json)）：`if` 只接受 idle、working，done 与多值都被拒；不带 `force` 时，`terminal.send` 拒绝 blocked 的程序，什么都不输入。
  - 执行主控据此定的送法（不是用户裁定）：
    - 一律不带 `force`，权限框、问答框由 hc 在同一次送入里拒绝；
    - 主控终端上报 idle 时，带 `if: "idle"` 送；
    - 上报 done 时不带 `if`，只在编排后台看到的最新状态是 done 时才送。这里有一个窄竞态：CLI 恰在这时自己开始新回合，文字就进了它正在工作时的输入，由 CLI 自己排队，仍只提交一次。等打包的 hc 让 `if` 能取 done 时，改成带条件送，并删掉这条说明。
- 用户输入记录：用户 2026-11-01：“agent 之间沟通用 hc,包括主控回答 worker 问题的最好也能走 hc,这样能区分开. 在终端输入的算是用户输入的,然后只记录我发送之后的完整的这一条,不要把输入过程中的操作以及其他琐碎的东西记录进去,只记录最终的我发的话”。
  - 主控终端里（Claude Code、Codex 有提交钩子）只记钩子报来的提交全文，一次提交一条；按键与输入过程不记。attach 看到的按键只用来判断用户是否正在输入、要不要暂缓投递。
  - 来源判断（执行主控决定，不是用户裁定）：一条提交的全文（只去掉 CLI 已知的改写，例如 Claude 去掉末尾换行和 `<pasted_content>` 包装）等于一条发往本终端、已写下 `hc_send_intent`、还没被认领的收件箱派发，就认领为系统投递，只认领一次，不记为用户输入。派发正文以唯一的 `⟦主控 #序号⟧` 开头并带收件箱条目的 UUID，这是我们自己写进去的来源标记。代价：后台在写下意图之后、真正发出之前退出，这条其实没送出；之后用户又逐字提交同一全文时，会被认成系统投递。主控接受这个后果。同一全文第二次出现仍记为用户输入。
  - 主控回答 worker：worker 窗格现在还是 node-pty，答复经原有派发写入；随受管窗格切到 hc（地图里的待切项）一起改走 hc，不在本票。worker 窗格里用户输入的记录方式见 [T-229](T-229-worker-input-final-text-only.md)。

## Acceptance

- [ ] 修前经真实入口留下红态：worker 上报问题后，执行主控终端收不到任何投递；标 blocking 的一上报就计入“等你决定”。
- [ ] 修后：非 blocking 与 blocking 问题上报后，执行主控终端各收到一条投递，内容含编号与原文；该投递不出现在用户输入记录里。
- [ ] 四家 CLI 当执行主控时都收到投递，各只实际提交一次；主控忙、遇权限框或问答框、终端里有用户未发出的草稿时不送入，等可接收后再送；送入后确认不了的记为未知，不自动重发。
- [ ] 主控答复后，答复送达上报的 worker 窗格，记为主控的回答；问题显示“主控已答”，不计入“等你决定”。
- [ ] 主控交给用户（附理由）后，问题计入“等你决定”，界面显示理由；用户答复记为用户输入（`reply_to` 该问题）。
- [ ] 反例：没有执行主控时上报，投递排队、问题不丢；15 分钟后计入“等你决定”。
- [ ] 角色卡与命令说明写明只交用户的类别。
- [ ] 独立审查（GPT 只读，新开干净会话）无未处理的阻塞意见。用户 2026-11-01 改分工：“antigravity 换用里面的 4 argon 模型可以做一些小任务, gpt 做审核,work 的工作由你在当前会话中做.”
