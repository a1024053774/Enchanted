## What to build

来源：用户逐字（2026-10-20，会话"a2a-构思主控"）："这个做完后应该不差什么了吧，给我做个产品页，用 GitHub pages 就像，用户在产品页前端就能点击这个软件的一些内容来操作，当然这些都是我们预设好的，就是在前端就能点我们软件的不同按钮之类的看效果，以及里面展示一些我们预设的想要表达的内容，这个由 claude 模型来做，然后同时构建打包笨笨，清理本地缓存，更新固 GitHub 仓库页面"

AskUserQuestion 逐字选项：产品页放置——"把仓库改个名字公开吧，改名叫 Enchanted，我应该有个 Enchanted 了，把那个归档吧，规划成我们这个 a2a 仓库的未来 feature"；打包范围——"再发布到 GitHub Releases"；产品名——"Enchanted,a2a 是其编排内核 (Recommended)"。

核实（构思主控 2026-10-20）：GitHub 上 a1024053774 名下没有 `Enchanted` 仓库，本地 `~/Documents/Code/Enchanted` 无 remote，故名字可用；a2a 仓库现为 private，免费账号 private 仓库不能开 Pages。

**由 Claude 模型来做**（用户明确指定；这是对"worker 用 Codex"的一次例外，仅限本票页面设计与实现。执行主控起 Claude Code 会话做，模型与强度走 T-112 的设置，沿用普通速度；写入范围限本票目录）。

1. 位置：本仓库内的纯静态站点目录（执行主控按 Pages 能直接发布的方式选 `docs/` 或其他，不依赖需要 `workflow` 权限的 Actions，先看 `gh auth status` 的 scope），不引入构建服务；外部库只从 cdnjs / jsdelivr / unpkg 取固定版本。
2. 内容（预设，由模型起草，中文；走 `document-writing` 与 `frontend-production` 的去 AI 味、同族要求，不写夸大的收益主张，首轮基线只写事实）：这是什么（Enchanted，a2a 是编排内核）、解决什么问题（多 agent 协作要有门禁而不是靠自觉）、核心机制（门禁：认领/交付/机械检查/独立审查/集成；写审分开；提示词管判断、脚本管事实）、两层主控、已有功能、路线图（旧 Enchanted 的功能作为未来 feature，写成路线图条目）、怎么下载（指向 GitHub Release）、开源协议 GPL-3.0 与 Synara MIT 声明。
3. **可点击的软件演示**：在页面里用前端还原工作台的主要界面，所有交互是预设好的（不连任何后端、不调模型）：侧栏项目与 agent 层级树和七种状态；点击切换项目/任务；右键窗格菜单（分屏、放大、重命名、关闭、转发右键）；提问面板里点选项作答、状态从"等待用户回答"回落、应用内通知；系统流程页（泳道、阶段、胶囊、折回线、"还有 N 个"展开）；终端里预设的几行输出。演示取材于真实界面：先看 `evidence/` 里已有的真实截图和 `workbench/app/*.css/tsx` 的样式，视觉与真实界面同族，不凭想象另起一套。
4. 手机宽度可用，深浅色主题，无横向页面滚动；演示区在窄屏上退化为可左右滚动的画布或分步引导；键盘可达。
5. 不含任何真实凭据、真实会话正文、本机路径与用户邮箱；演示数据全是虚构夹具。
