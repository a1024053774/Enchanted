## Question

T-121 的已知边界：操作员凭据（用来批准角色申请的管理凭据）是后台数据目录里的一个 0600 文件，终端环境导出了 `A2A_STATE`，同一用户的 agent 能读到它，自己批准自己。用户 2026-10-21 逐字：“这个不能放内存里吧,要持久化,钥匙串也没必要,你找一种合适的持久化方法”。

## Facts

- 凭据需要持久化：编排后台常驻，界面关掉再开要重新连上后台。
- 同一个 macOS 用户的进程能读这个用户能读的任何文件。只要 agent 在用户自己的终端里、能执行命令，不论文件放在哪里、权限怎么设，它有意去找就能读到。文件存放方式只能挡住“顺着环境变量找到”和“按说明误用”，挡不住有意搜索。
- 能真正挡住同用户进程的只有操作系统层的保护：钥匙串条目限定只允许 Enchanted 应用读取（别的进程读取会弹系统确认），或者让后台以另一个系统用户运行。
- 和存放无关、本来就该做的一步：终端只拿到一个只接受终端身份的专用 socket 路径，环境里不再出现后台数据目录。

## Options

- A：凭据文件移到 `~/Library/Application Support/Enchanted/` 下的 0600 文件，终端改用专用 socket，环境里不出现数据目录。持久化、无需系统确认；挡住顺着路径读取，挡不住有意搜索磁盘的 agent。
- B：A 的专用 socket，加上凭据存进钥匙串并限定只允许 Enchanted 应用读取。真正挡住同用户的 agent；首次需要系统确认一次，应用重新签名后可能再确认。
- C：A，再加上批准时要求界面里的人工操作证明（例如批准按钮只认主进程按用户点击当场生成、不落盘的一次性码）。仍是同用户可绕开的软件约束，比 A 难绕，但不如 B。

## Recommendation

B。用户说“钥匙串也没必要”时，可能没有掌握“文件放哪都挡不住同用户 agent”这个事实；如果用户接受“只防顺手误用、不防有意绕过”，选 A。

## Decision

2026-10-21 用户选 A（逐字：“T-121 选 A”，指本票的选项 A）。凭据文件移到 `~/Library/Application Support/Enchanted/` 下的 0600 文件；终端改用只接受终端身份的专用 socket，终端环境里不再出现后台数据目录。已知并接受的边界：挡住顺着路径读取与按说明误用，挡不住有意搜索磁盘的 agent。
