## What to build

起因：内置盘只剩约 4.9 GiB。用户 2026-10-18 在构思主控会话说："把证据归档到外置硬盘"。

用户的两条裁定（AskUserQuestion，逐字选项）：
- 范围：「B A 加上已入库的大目录（约 5.3 GB）」——即 A（被 git 忽略的 `*-artifacts/`，约 1.3 GB）加上已入库的旧批次大块。这等于**放宽 T-088 的"已提交历史不改写"只对工作区**：git 历史不改写，历史里仍有这些文件；工作区里删掉并留清单。
- 删除时机：「核对一致后自动删」——文件数与字节数核对一致后自动删原目录，**不另设用户确认步骤**（用户明确选了这条，不用 T-089 的两阶段确认）。

做法（沿用 T-088/T-089 的归档工具与 `*.archive.json` 清单格式，不新造）：

1. 范围：`evidence/` 下 batch16 之前的批次里，符合 T-088 类别的大块（run/fixtures 目录、`*.tar.gz`、`*.bin`、sqlite、监视器日志、被忽略的 `*-artifacts/`）。batch16 及以后不动（已按 T-088 处理）。
2. **保留不归档**：被测试、门禁、脚本或任何未关闭 ticket 当输入读取的文件；文本摘要（RESULTS.md、审查报告、controller-decision、命令脚本、run.json 摘要）。动手前先全仓检索引用，凡有引用的留在原处并列入清单。
3. 归档到 `/Volumes/WD-Elements/a2a-evidence/<批次目录>/<ticket>/`，仓库留 `*.archive.json` 清单。外置盘未挂载就报错，不回退内置盘。
4. 每个目录：复制 → 核对文件数与字节数一致 → 一致才删原目录；不一致保留原目录并报 INCOMPLETE。逐目录处理，一个失败不影响已完成的，不删任何核对失败的。
5. `.runtime/`、`workbench/node_modules`、`../a2a-wt-t093` 与用户缓存不在本票范围。
6. 先出清单（目录、大小、是否有引用）再动手；清单与结果写进本票的 Resolution。

## 裁定（2026-10-18，执行主控盘点后）

盘点显示按原规则只能释放约 0.91 GiB。用户选项逐字：「A 只放宽类别：所有大于 5 MiB 的文件都归档」。即类别扩到 batch16 之前旧批次里**所有大于 5 MiB 的文件**（普通 JSON、日志等），被现存测试或脚本读取的输入仍保留原处，不改引用方（选项 C 未选）。预计再释放约 0.9 GiB，合计约 1.8 GiB。已入库部分要合入 main 后才真正释放。
