## What to build

把 [T-055](T-055-issue-report-tracer-bullet.md) 的单条路径补成完整的使用体验：

- 处置：主控可以判断并关闭"不是问题"，拿不准的转"等你决定"，设计级的转交构思主控，用户可以重开、稍后、不处理；全是追加记录，不删不改。
- 视图：默认只显示"等你决定"，可切到"全部"和"已关闭"，关闭项带理由与依据。
- 回复：每题有回复框，草稿存本机；已答多题可以"逐个发送"或"打包发送"，打包按会话各一条，格式见 [spec](../specs/controller-split-user-input-2026-10-09.md) 第 4 节。
- 提醒：计数徽标、软件内通知；需要用户做决定的才走系统通知。

## Acceptance

- [ ] 红态在先：父修订上缺这些能力，用例失败；保存输出与重放命令。
- [ ] 处置动作（界面、CLI/HTTP、MCP 走同一核心）：`close`（必须带理由与依据）、`needs-user`、`forward`、`reopen`、`snooze`（1 小时）、`dismiss`（仅用户）、`delivered`。每个动作追加一条处置记录，原条目不改不删；状态按 spec 第 4 节派生；判断期内无处置的算"待判断"，超过判断期的算"等你决定"（注入时钟验证）。
- [ ] 服务端强制的那一部分"不许自行关"：标 `blocking` 的上报被主控角色 `close` 时被拒绝，只有用户能 `dismiss`。其余类别（权限、范围、验收条件、安全、不可逆操作、选择题、拿不准）靠角色卡，不做内容判断，也不用正则。
- [ ] 面板：默认只显示"等你决定"；可切到"全部"和"已关闭"；关闭项显示理由与依据，可一键重开；blocking 置顶；每个会话旁与项目侧栏有"等你决定"计数徽标。保存截图，外观由用户判断。
- [ ] 草稿：每题回复框的草稿存本机，刷新或重启应用后还在，发送后清除。
- [ ] 发送：单条"发送"；已答 ≥2 题时默认"打包发送（N）"，也可改为"逐个发送"；未答的不参与；按会话各打一包。打包串逐字等于 spec 第 4 节的预期串，预期由需求手写，覆盖：问题号取会话内编号而非位置；正文超过 600 字符时截断并以"…"结尾；无正文时省略该行；题间一个空行；无头无尾。
- [ ] 记录：每题一条形态为 `answer` 的用户输入，`reply_to` 该问题；同一包共享 `bundle_id` 并记下送达消息的 id；该包在线程里只有一条来源为 `user` 的消息，不重复记录。逐个发送时每题各一条消息。
- [ ] 送达：已送达的题派生为"已送达"；会话已结束时不送达，答复照记，并对执行主控产生一条 `forward`（理由 `session-ended`），在其未确认列表里可见。
- [ ] 关闭告知：issue 被关闭后不单独起 turn；提问会话的下一条经面板或门禁送达的消息末尾附一段告知（格式见 spec 第 4 节），只附一次。
