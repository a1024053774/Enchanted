## What to build

来源：用户 2026-10-19 在构思主控会话逐字（附 Herdr 侧栏截图，上半是 spaces 项目列表，每项两行：项目名、分支和领先提交数，带状态图标；下半是 agents 分组列表，每项：项目 · 名字、agent 名，带状态图标，当前选中高亮）：

"就像 herdr 当前这样,可以添加项目目录,然后选择每个目录就是每个项目,里面各个 agent 角色,然后下方有 agent 的运行状态,不过我们要做的更好,要显示 agent 的层级关系,也就是我们设置的主控,worker 这些,还要有状态显示,显示他们是在运行,还是等用户输入,比如提出问题等待用户回复那种,还有就是 idle 状态这些."

在 T-103 的"项目 → 任务"列表和 T-105 的窗格基础上改成这个侧栏（与 T-106 同改界面文件，故 blocked_by T-106）。

1. **项目区（上）**：列出项目目录，每项两行：项目名、当前分支与相对上游的领先/落后提交数（读该仓库的 git 事实，不猜）；"新增项目目录"入口复用 T-106 的项目注册，不另做一条；选中项目后右侧显示它的任务与窗格。项目行的状态图标取其下 agent 状态的汇总（有等待用户回答的最醒目，其次运行中，其余空闲）。
2. **agent 树（下）**：按层级缩进列出所选项目（或全部项目分组，可切换，同 Herdr 的 grouped）里的 agent 会话：构思主控 → 执行主控 → worker / reviewer / monitor；worker 等挂在它所属任务下。每项显示：角色名（中文：构思主控、执行主控、worker、审查员、监视器）、任务号与 attempt、CLI（claude/codex）、状态图标与状态文字。点击聚焦对应窗格。
3. **层级来源**：只用 a2a 已保存的事实——启动记录里的角色、任务与 attempt 绑定、派发记录里的派发关系；不从窗格标题或终端文字猜。关系不明的会话显示在"未归属"下，不硬挂。
4. **状态集合与来源**（逐字中文）：运行中、等待用户回答（agent 向用户提了问题，如 Claude 的 AskUserQuestion）、等待主控回答（worker 向主控提问，沿用 T-095 的识别）、空闲、已结束、未恢复、未知。来源是现有结构化状态信号和 `scripts/agent-status`（T-095 已区分等待主控回答），以及 Herdr 之外的工作台自己的窗格状态；**识别不到就显示"未知"，不上调成运行中或空闲**。"等待用户回答"若现有信号区分不出，列为缺口并上报，不用屏幕文字正则或关键词判断（项目规则：语义识别不靠正则）。
5. **状态变化提示**：等待用户回答出现时，侧栏该项与所属项目行高亮，并有一次系统通知（可在设置关闭）；只通知"等待用户回答"，不通知普通运行/空闲变化。
6. 视觉：参考 Herdr 的密度与图标语言（圆点/半圆/对勾/空心圆的含义要在界面里有图例），文案中文，走 `frontend-production` 去 AI 味与同族要求；窄侧栏下不截断关键信息（项目名、角色、状态）。

## Acceptance

- [ ] 红态：当前没有项目侧栏与 agent 树。绿态：真实 Electron，夹具里有 ≥2 个项目；其中一个有构思主控、执行主控、2 个 worker、1 个 reviewer，层级缩进正确，点击聚焦对应窗格。
- [ ] 状态：用真实（或已记录的真实原件回放）信号覆盖运行中、等待用户回答、等待主控回答、空闲、已结束、未恢复、未知七种；**反例**：信号缺失时显示"未知"而不是运行中/空闲；关系不明的会话进"未归属"。
- [ ] 项目行汇总：有等待用户回答的项目行最醒目，回答后恢复；系统通知只在进入"等待用户回答"时触发一次，可关闭。
- [ ] 分支与领先提交数与 `git status -sb` 一致；新增项目目录与 T-106 的注册结果一致。
- [ ] 真实入口截图与复现命令入证据；真实模型回合数照实记录；`project_map.py status` 0 问题。
