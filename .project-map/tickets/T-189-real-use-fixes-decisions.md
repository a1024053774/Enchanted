## Question

用户 2026-10-27 两次真实使用后反馈“现在我是无法使用的”，并说“咱们先一起定一下方案”。问题清单 U01～U11 [findings/2026-10-27-two-real-uses.md](../../findings/2026-10-27-two-real-uses.md)

## Resolution

用户 2026-10-27 在四个选项问题里各选了推荐项（选项标签逐字）：

1. 主控身份与项目：“主控可管多个项目”——身份绑终端，不绑启动目录；主控可在任何已打开的项目里建任务；跨仓库的事拆成每仓一个任务，各自审查、集成。落地 T-193。
2. 项目移除：“随时可移除，历史保留”——移除只是从列表隐藏，任务与记录留在库里，重新打开目录即恢复；有未回收 attempt 时弹窗问是否一并回收；目录已删的项目标“目录不存在”，不再拖累其他项目。落地 T-190。
3. 派发入口：“MCP 为主，命令兜底”——后台提供 MCP 工具（申请角色、建卡、派发、验收），接不上 MCP 的 CLI 退回 `a2a` 命令；两条入口进同一个门禁，不另做一套。先实测四家 CLI 对 MCP 的支持。落地 T-194。
4. 复制深度链接：“CLI 名 + 原生会话 ID + 记录路径”——拿不到原生 ID 的 CLI 菜单项置灰并说明。落地 T-195。

按推荐做法、用户未反对的两项：每个 agent 前加 CLI 图标（T-191）；任务页无论有没有存活窗格都显示任务卡、attempt 时间线、检查结果、审查报告、打分与提交（T-192）。

已有事实（不需新做）：尾注由门禁装进 worktree 的 `prepare-commit-msg` 钩子写入并在交付时核对；打分是验收命令的必填项。
