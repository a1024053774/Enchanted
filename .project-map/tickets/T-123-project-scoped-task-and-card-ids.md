## What to build

来源：T-121 第 3、4 轮审查（`evidence/2026-10-21-batch19/T-121/review-03.md` 的 B2，`review-04.md` 建议 4）与用户 2026-10-21 的决定。用户逐字：“按理说两个项目在不同的文件夹路径下,怎么会改写其他项目的文件呢?或者这个卡片是我们 a2a 软件的卡片,那这个冲突要解决”。

事实：任务卡不是项目目录里的文件，而是 a2a 后台库里的记录（`task_card_versions` 只按任务 id 记，`tasks` 的主键也是任务 id）。任务 id 在所有项目之间共用一个命名空间，所以两个项目起了同名任务就会互相占用。T-121 用“首次保存的终端项目拥有该草稿”挡住了越界读写，但没有消除冲突：一个项目先占了某个 id，另一个项目就再也用不了它。

用户 2026-10-21 确认方向（逐字）：“这个按项目各自独立,迁数据”。

要做的：任务和任务卡的身份带上项目。同名任务可以分别存在于不同项目；门禁的读写、事件、侧栏、流程页、提交尾注都按“项目 + 任务”定位。已有数据迁移到新身份，不丢记录。T-121 加在后台的草稿归属（`card_draft_owned`）随之删除，不保留两套。

## 实现方案（2026-10-22，执行主控）

- 门禁内部的任务 id 改为 `<项目>+<任务名>`（如 `demo+T-1-1`）。项目 id 与任务名都只含 `[A-Za-z0-9_.-]`，`+` 不会造成歧义，且可用于文件名与 git 分支名。库表、锁、事件、分支、worktree 因此都按项目区分；门禁内部不改为复合键，避免逐处改漏造成跨项目串号。
- 请求里的 `task` 可以写完整 id，也可以写任务名。写任务名时，项目取终端角色的项目或请求的 `project`；管理凭据不带项目、且任务名在多个项目重名时拒绝（`task_ambiguous`）。
- 任务记录加 `name`；侧栏与流程页显示任务名，提交尾注写完整 id。
- 迁移在后台启动时做：把旧任务名改写成完整 id，范围是各表的任务列与 JSON 里的 `task_id`、`task`、`task:` 引用，迁移前后逐表核对条数；草稿卡片按 `card_draft_owned` 归入项目，之后删除 `card_draft_owned`。
