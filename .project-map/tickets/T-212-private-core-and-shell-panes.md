## What to build

依据 [T-209](T-209-hc-as-runtime.md)、[规格](../specs/hc-runtime-2026-10-31.md)。用户在工作台里打开项目终端时，终端由编排后台启动的私有 hc core 托管，而不是编排后台自己的 node-pty。从用户这边看，项目终端的样子和操作不变；不同的是编排后台重启后，项目终端里正在跑的程序还在，窗格接回原样。

这是最薄的一刀：只换项目终端（用户在里面自己启动 CLI、经角色申请当主控的那种），受管窗格（worker、审查员、监视器）留给下一张票。

- 应用带固定版本的 hc（版本与来源按 T-211 的结果），编排后台用 Enchanted 专属的 `HC_SESSION` 启动私有 core，脱离调用者的进程组。
- 项目终端的输出经 hc 的 attach 流进窗格；按键经编排后台写进 attach 通道，现有的用户输入记录、角色申请、`a2a` 命令包装照常工作。
- 项目终端原来的 node-pty 路径删除，不保留两套。

## Acceptance

- [ ] 修前经真实入口留下红态：编排后台重启后，项目终端里正在运行的程序随之结束。
- [ ] 修后同一操作：编排后台重启，项目终端里的程序仍在运行，窗格接回后屏幕与历史完整。
- [ ] 应用启动时私有 core 由打包的固定版本 hc 启动；用户自己 Herdr 的 core 在测试前后的终端列表不变，私有 session 的终端不出现在用户的 Herdr 里。
- [ ] 项目终端里打字、粘贴、中文、Esc、Ctrl-C 与改前一致；用户输入记录与改前一致。
- [ ] 在项目终端里启动 Claude Code 并经 `a2a request` 申请主控、界面批准后生效（T-119 流程不变）；侧栏状态与改前一致或更准，不出现新的“未知”。
- [ ] 打包产物里含 hc 二进制与其 Apache-2.0 许可声明。
- [ ] 项目终端不再经 node-pty 启动（代码里没有第二条路径）。
- [ ] 独立审查（agy 只读）无未处理的阻塞意见。

## 不做

受管窗格（worker、审查员、监视器）换运行时；状态改取 hc 事件；父子通知。
