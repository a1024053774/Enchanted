## Question

换成原生 CLI 加 a2a 自己的工作台以后，权限怎么分层？怎么判断 agent 在跑、在等确认还是结束了？派发和主控唤醒怎么送进去？数据放哪？构思主控要问用户的问题怎么给用户？

## Resolution

2026-10-10 grilling 确认。账本 [native-cli-orchestration](../../.grilling/native-cli-orchestration.md) 的 D9、D14、D15、D17、D27 与 C6；设计见 [spec](../specs/native-cli-orchestration-2026-10-10.md) 第 5–7、9 节。

- **权限四层**（D9），都在工作台内：① 角色卡；② 任务卡的允许/禁止路径，由门禁检查交付；③ 每个会话的 CLI 启动参数，只作用于该会话，不碰 `~/.claude`、`~/.codex`（例如审查者的 Codex 只读沙箱）；④ 收件箱命令行限定谁能写哪种条目。设置页的"角色权限"编辑启动参数与路径规则，默认按此。用户 2026-10-09 的纠正仍然适用："不是让你在Claude code和codex里改权限"。
- **状态信号**（D14）：只认各家结构化信号（Claude Code 的 hooks 与 OSC 7501，Codex 的 `notify`），拿不到的状态显示"未知"，不用正则匹配屏幕或标题；钩子只经本会话的启动参数传入（Claude `--settings`，Codex `-c`）。
- **派发与唤醒**（D15）：派发文本写进 worker 窗格，带 `⟦主控 #序号⟧` 标记，记派发日志，不算用户输入；两个主控也作为窗格跑在工作台里，互相唤醒改为往对方窗格写带标记的提示；收件箱条目仍是事实来源。
- **数据**（D17）：用户输入、问题上报、收件箱、门禁都放编排后台的同一个 SQLite 库，只追加；`scripts/inbox` 改为后台的命令行客户端；`.project-map/inbox/` 文件在切换当天退役，不双写；切换前 Herdr 期照旧用文件。
- **主控提问进面板**（D27）：构思主控用命令把问题放上面板，每题带类型、选项、推荐和依据；用户逐题点选、采纳推荐或写几句，草稿自动保存；沿用 2026-10-09 的发送规则，可逐个或打包发送，已答两题以上默认打包，格式"问题 N：…… / 用户答复：……"，写进构思主控的窗格，每条答复记为 `answer` 用户输入并指向问题；执行主控的 needs-decision 由构思主控改写后放上面板；用户在对话里答的，面板标"已在对话中答复"；Herdr 期照旧在对话里问。用户的话："比如构思主控需要一些我回复的问题的时候，可以把这些问题放到面板上来？我回复完再传回去，这个方式我之前应该说过，批量和逐个这些。"

与旧决定的关系：[T-049](T-049-controller-roles-and-permissions.md) 的层级与分工不变；它的"权限三层"在第三阶段载体上改为本票的四层，"Synara 期用能力预设"改为每会话启动参数；按任务卡路径的检查是门禁对交付的核对，不是写入时的拦截。[T-050](T-050-user-input-records.md)～[T-052](T-052-controller-handoff-protocol.md) 的语义沿用，载体从 Synara 换成工作台：用户输入在窗格的终端层记录，唤醒由跨会话消息改为窗格注入。

被否决：用正则读屏判断状态（Herdr 的做法，三个月改了 10 次）。
