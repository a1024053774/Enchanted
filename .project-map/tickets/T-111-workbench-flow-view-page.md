构思主控据此的理解（用户未逐条确认，有硬冲突上报）：

1. **单独页面**，与侧栏缩进树（T-109）并存，主区加"流程"标签；只读展示，不在这里派发或操作。
2. **一张票一条横向泳道**：并行的任务票上下并排，每条泳道左端是票号与标题；泳道里从左到右是该票的门禁阶段（认领与实现 → 交付 → 机械检查 → 独立审查 → 集成），节点之间用 ››› 表示推进；机械检查或审查打回时画折回线回到实现阶段（折回次数来自门禁事件的事实，不猜）。
3. **每个阶段列**：阶段名下竖排此刻在该阶段干活的 agent 胶囊，例如实现阶段两个 worker、审查阶段一个 reviewer；胶囊左边的彩色点表示 agent，右边是名字与角色，并带 T-107 的状态图标（运行中、等待用户回答等）；超过 4 个折叠成"还有 N 个 ↗"，点开展开。
4. **数据来源**：阶段取门禁事件（事实）；agent 归属取 T-109 的父 launch 与启动记录里的任务/attempt 绑定；角色决定放哪一阶段（worker 在实现，reviewer 在审查，monitor 贯穿，放泳道上方）。归属不明的放"未归属"。不凭窗格文字猜。
5. 泳道已完成的阶段变灰，当前阶段高亮；已集成的票默认折叠；整张图可左右滚动，窄窗口不压坏布局。
6. 视觉走参考图的密度与圆角胶囊语言；文案中文，走 `frontend-production`（去 AI 味、同族）。
