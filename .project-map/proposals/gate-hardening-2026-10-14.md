# 门禁加固：验收标准保护、坏 worker 测试集、完成条件审查（2026-10-14 决定记录）

来源：用户 2026-10-13 至 10-14 在旁路会话“A2A 多Agent协作的确定性架构”中，结合一次模拟面试（得物 AI 开发岗，原始对话 `~/Downloads/模拟面试 Agent 开发__6acba922.json`，不入库）讨论 a2a 的改进方向。本记录只写已定的取舍和依据，不切 build ticket；切票、标就绪和派发由构思主控负责。

## 背景结论

面试官建议的多数机制，门禁已经实现：task/attempt/fence 绑定与 `stale_attempt` 拒收、CAS 快进集成、在合并结果 M 上跑完成条件且基线变化后 `stale_verification`、红态检查、每次交付新开只读 reviewer 并绑定候选、同一 attempt 打回 3 次后暂停、尾注身份核对。以下三项是本次核对源码后发现的真实缺口。

## 决定

### D1（P0）验收标准本身由门禁保护

- 事实：完成条件以 argv 在验证工作区执行（`workbench/src/gates/core.ts` 约 2847 行），路径边界只按 `paths.allow` / `paths.deny` 判断（`workbench/src/gates/taskCards.ts` 的 `pathAllowed`），`allow: ["."]` 合法。门禁不检查完成条件所依赖的测试或脚本是否被候选修改。验收文件受不受保护，取决于执行主控写卡时是否记得把它们放进 `deny`，这属于软约束。
- 做法建议：任务卡增加显式字段（暂名 `oracle_paths`），列出完成条件依赖的测试、脚本和配置；门禁机械检查候选改动与它是否有交集，有交集就拒收，并把打回原因单独记为一类。worker 认为验收测试有误时，走问题上报，由主控或用户改卡，不能自己改。
- 字段名称、是否允许为空、与 `red_commands.test_paths` 的关系（红态测试必须由候选新增或修改，不能与 `oracle_paths` 冲突）由构思主控切票时确定。

### D2（P0）门禁的坏 worker 测试集

- 把下列坏行为写成脚本化的执行者，在真实门禁入口逐个证明会被拒绝，并保留红态和反例：改验收测试或验收入口（依赖 D1）；只交一句“所有测试通过”的自报；旧 attempt 迟到提交；验收后再改候选；改动越出 deny 路径；缺尾注或伪造尾注。
- 增加一项本会话未核实的能力检查：worker 会话是否能对共享仓库执行 `git update-ref` 或 `git push`。门禁不放行，不等于 worker 没有这个能力，要用真实 worker 会话试一次。
- 同一套里放正确交付的正例，用来统计误拒绝。

### D3（P1）reviewer 审查完成条件是否够格，并在审查中做变异检查

- 完成条件由执行主控（LLM）撰写；它能否覆盖 ticket 的验收要求、能否拒绝错误实现，是判断题，不做成规则。在 reviewer 角色卡和审查请求中加入必查项：完成条件是否足以拒绝明显错误的实现。
- 变异测试在 reviewer 内做，不单独建平台：reviewer 针对候选的关键逻辑构造少量错误实现，确认完成条件或新测试会失败，并把结果写进审查报告。
- 待构思主控处理的冲突：reviewer 角色卡现写“不改被审查的代码”。变异只能在 reviewer 自己的一次性副本里做（例如审查工作区 `verification/review-<id>` 之外的临时副本），不得改动候选、不提交、不进入集成路径；角色卡措辞需相应调整。

## 不做或搁置

- 提交前的期限：不做。用户认为有的任务本来就很长，不应给提交设期限。
- 跨任务接口契约与变更请求（P2）：搁置。
- reviewer 同模型相关性的交叉审查实验（P2）：搁置。
- 租约 TTL 加心跳的自动重派：不做。a2a 换 attempt 是显式操作，fence 已保证旧结果进不来。
- 单独的变异测试平台：不做，见 D3。
- 自动判断任务该走单 Agent 还是 a2a：以后再说。

## 授权

用户原话（逐字，2026-10-14，旁路会话“A2A 多Agent协作的确定性架构”）：“两个 P0 都做，第一个 P1 做，第二个 P1 没必要给提交设置期限吧，有的任务很长可能需要很久，两个 P2 先搁置。然后变异测试可以做，就比如在 reviewer 里做，平台倒是没必要单独做，自动判断任务以后再说，现在你在 herdr 里，你去和构思主控与执行主控沟通”

对应关系：“两个 P0”= D1、D2；“第一个 P1”= D3 的完成条件审查；“第二个 P1”= 提交前期限（不做）；“两个 P2”= 跨任务契约、reviewer 交叉审查。

按 AGENTS.md，D1、D2 改变门禁行为与验收规则，属于验收条件变化；本条授权覆盖“做这三项”的方向，具体验收条件由构思主控写进 ticket。
