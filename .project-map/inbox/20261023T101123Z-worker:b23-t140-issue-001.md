# 临时目录的原生写权限与移除语义

状态：INCOMPLETE（源码观察，尚未做原生复现）。T-140-1 / a1，worker b23-t140。

`workbench/src/panes.ts` 的 `createPane` 目前只对 reviewer 设置
`sandbox_workspace_write.exclude_slash_tmp=true` 和 `exclude_tmpdir_env_var=true`。
普通 Codex worker 原有的 `/tmp` 与 `$TMPDIR` 写权限仍在，T-140 不会收紧它们。
如果用户把这些默认已可写位置里的目录登记为额外目录，移除登记不能撤销 CLI 的默认临时目录写权限。
因此，“移除额外目录后新会话写不进去”不能无条件覆盖本来就可写的位置；主 worktree 内的子目录也有同样边界。

新 e2e 把 X/Y 放到独立的 `/Users/Shared/t140-extra-*` 夹具，避免默认临时写权限污染负例。
没有据此宣称默认临时目录被隔离，也没有修改其他 worker 正在负责的 T-141 权限配置。

建议由执行主控将此问题交给 T-141 协调：明确允许的临时位置，以及额外目录移除对本已可写位置的语义。
如要把普通 worker 的临时目录排除，应同时给 CLI shell 准备可写临时目录，保留请求目录写入，取得独立红绿证据。
这会触及现有原生权限与临时文件行为，故本 worker 不顺手修改。T-140 针对独立外部目录的实现继续。
