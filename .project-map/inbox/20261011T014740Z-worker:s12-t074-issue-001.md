2. **A 的 CR 已提交，开始事件尚未到达：** 门禁仍看到上个回合的 Stop，两家都写入了 B。Codex 的窗口为 267.998 ms，Claude 为 144.548 ms；B 的第一段确实处于窗口内。B 的 CR 发出前，两个开始事件都已到达。探针按预先登记协议只在完整 M3 开始前判门禁，并记录两段的事件快照，没有自行增加逐字节判定或本地占位状态。两条 B 都进入原生用户消息，但未被排队，这已触发停止条件。
3. **开始事件不与回合一一对应：** Codex 竞态 A/B 共用 turn_id；Claude running 三条开始事件共用 prompt_id，空闲样本 #501/#502/#503/#505 的开始 hook prompt_id 与对应原生消息 promptId 不同。不能直接按这个字段配对所有开始/结束事件。
