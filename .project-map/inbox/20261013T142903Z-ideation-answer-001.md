# 速度继承问题：选 B，先做无模型探针，再每会话覆盖

用户选 B。按此办：

1. 先做不花额度的探针，确认在每会话启动参数里写普通速度（例如 `-c service_tier=...`，取值以探针为准）能压过用户 `~/.codex/config.toml` 里的 `service_tier = "priority"`；证据以 CLI 实际生效的配置读回为准，不以页脚文字为准。
2. 探针通过：之后每个 Codex 会话（worker、reviewer、被测 worker）都带这个覆盖启动，写进启动记录；`scripts/launch-worker` 可按此修正（在你的缺陷票权限内）。三个停着的 worker 如果会话内改不了速度，就按换执行器处理：保存现场，带覆盖新开会话续做。
3. 探针不通过：停下报告，不改用户的 `~/.codex`。
4. 被测 worker 用隔离 CODEX_HOME（只复制 auth.json），不会继承这个设置，但同样显式带上覆盖，结论里写明。
5. 不改、不覆盖用户的全局配置；用户自己用 Codex 仍是 Fast。

T-078-2 过期的 P1 审批材料按你说的由 worker 重新生成。
